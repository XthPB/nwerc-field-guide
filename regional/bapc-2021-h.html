Hamiltooonian Hike

Order every cabin once so consecutive overnight stops are at graph distance at most three in a connected undirected graph.

The observation

Use any DFS spanning tree. Print even-depth vertices when entering them and odd-depth vertices when leaving them, or reverse the parity convention. Each vertex is printed exactly once.

Why it works

Along a tree DFS walk, alternating entry/exit events ensure that between consecutive printed vertices at most three tree edges are traversed. A turn between subtrees crosses at most an unprinted parent and one child before the next selected event. Tree edges are original graph edges, so graph distance is no larger.

From a small instance to the contest constraints

Enumerate all cabin orders

Check consecutive all-pairs distances for every permutation. This highlights that only the order of overnight stops matters.

Small-instance oracle · O(n!·n) after distances time · O(n²) space

Hamiltonian path DP in the graph cube

Connect two cabins if their original distance is at most three, then run subset Hamiltonian-path DP. Correct but ignores the constructive theorem that makes every connected instance solvable.

Exact but exponential · O(2^n n²) time · O(2^n n) space

Plain DFS preorder

After finishing a deep subtree, the next preorder vertex may be far away. The traversal walk is legal, but printing only first visits loses the three-edge distance bound.

Incorrect shortcut · O(n+m) time · O(n) space

Alternating entry and exit

Parity interleaves the descent and return stops so no long gap remains.

Recommended mathematical construction · O(n+m) time · O(n) space

Iterative DFS events

Use an explicit stack of frames (vertex, next-neighbour index, depth). Emit on entering or leaving according to parity. Build a spanning tree first if that makes the event logic simpler.

Recommended robust implementation · O(n+m) time · O(n) space

Boundary checks

This does not require a Hamiltonian path in the original graph: a day can contain up to three trails and may pass through previously visited cabins without sleeping there again. With n up to 200000, prefer an iterative traversal to avoid stack overflow.
