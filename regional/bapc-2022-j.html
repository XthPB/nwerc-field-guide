Jagged Skyline

A hidden skyline has one building height per column. You may ask whether a chosen pixel is building or sky. Find a tallest column and its height within the query budget, even though a height can be as large as 10¹⁸.

The observation

First test whether a column beats the current record with a query at bestHeight+1. Only record-breaking columns need a full height search. In random order the expected number of strict records is at most the harmonic number H_w.

Why it works

For distinct heights, the i-th processed column is a record with probability 1/i; ties can only reduce strict records. Linearity of expectation gives H_w expensive searches. Each uses at most ceil(log2(h+1)) queries. This is a probabilistic query-bound argument, not a worst-case guarantee of fitting 12000 for every random permutation.

From a small instance to the contest constraints

Binary search every column

Correct in value but up to roughly 600000 queries. The huge coordinate range demands avoiding most searches.

Budget failure · O(w log h) queries time · O(1) space

Walk along the skyline boundary

A staircase scan is good when h is small. Here h can be 10^18, so a bound involving every height level is unusable.

Wrong bound for this input · O(w+h) queries time · O(1) space

Search only deterministic records

Ask best+1 first and search only if the answer is building. An increasing skyline makes every column a record, so this alone does not solve the query limit.

Correct, adversarially expensive · O(w log h) worst case time · O(1) space

Random-order record search

Shuffle columns uniformly and apply the record filter. This is the core jury idea; the fixed non-adaptive interactor makes random order meaningful.

Recommended probabilistic approach · Expected O(w+log w·log h) queries time · O(w) space

Exponential search above a record

After best+1 succeeds, double the upward gap until you see sky or reach h, then binary search the bracket. This helps when records improve only a little; it still relies on randomisation for the overall budget.

Optional refinement · O(log(Δ+1)) queries per improvement time · O(w) space

Boundary checks

Use a genuine unbiased shuffle. Stop when bestHeight=h so you never ask above h. Flush each query. A correct returned maximum is different from a guaranteed query budget: the randomised method has a small failure probability, which should be acknowledged.
