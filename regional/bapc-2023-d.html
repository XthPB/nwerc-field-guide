Combinatorics and counting · BAPC 2023-D

Democratic Naming

Each city name has m letters. Construct a county name by choosing the most frequent letter at each position, breaking ties alphabetically.

The observation

Positions are independent; no choice in one column changes the votes in another.

Why it works

At column j, the statement’s rule is exactly argmax over letter counts, with the alphabetically smallest maximizer. Solving every independent column produces the required whole name. A left-to-right scan of the alphabet that updates only on a strict improvement implements the tie rule.

From a small instance to the contest constraints

Try every candidate letter against every city

For each column and letter, rescan all city names and count votes.

Valid baseline · O(26nm) time · O(1) beyond input space

Sort each column

Gather letters in a column, sort them, and find the longest equal run. Ties are naturally resolved by first occurrence in alphabetic order.

Alternative · O(mn log n) time · O(n) space

Frequency array per column

A fixed alphabet makes hashing unnecessary. Count once per column and choose the first maximum.

Recommended · O(nm+26m) time · O(26) space

Streaming column counts

Read one name at a time and update all column counts. The original names need not be retained.

Memory-efficient input handling · O(nm+26m) time · O(26m) space

Dynamic updates to names

If a city changes its name, decrement the old letters and increment the new ones, then recompute only changed columns. This illustrates maintaining sufficient statistics instead of the full voting history.

Advanced variant · O(m·26) per edited name time · O(26m) space

Boundary checks

Do not choose the most common whole city name. Use strict > when scanning letters in ascending order so equal counts preserve the smaller letter.
