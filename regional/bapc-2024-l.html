Greedy, sorting and search · BAPC 2024-L

Levelling Locks

Lock chambers lie in a row with known water levels. Start in one chamber and repeatedly add its left or right neighbor, mixing the joined water. Find an order that reaches every chamber while keeping the joined level at or below the final overall average throughout.

The observation

Reverse time. Instead of growing an interval, remove one endpoint at a time while the remaining average stays below the target. Center values by subtracting the target average.

Why it works

Use b_i=n·a_i−Σa, so all arithmetic stays integral and Σb=0. A remaining interval is safe iff its sum is ≤0. In reverse, a sequence of endpoint removals is safe iff every intermediate removed sum keeps this condition. Removing a safe block whose total is nonnegative only lowers the remaining sum, so it cannot invalidate any future opposite-side removals. Choose the shortest such safe block; alternate sides when one cannot supply a block. The jury’s exchange argument shows that if neither side can advance safely to such a block, no complete order exists.

From a small instance to the contest constraints

Enumerate starts and expansion orders

Choose a start, recursively expand left/right, and reject as soon as the interval average exceeds the final average. This is the cleanest oracle.

Tiny inputs only · O(n·2^n) time · O(n) space

Interval DP with reconstruction

A safe interval is reachable if it is a singleton or can be obtained by adding one endpoint to a reachable smaller interval. Store the predecessor endpoint.

Small n only · O(n²) time · O(n²) space

Reverse deletion DP

Start from the entire interval and remove a left or right endpoint if the new remaining interval is safe. This makes the monotonic resource interpretation visible and leads to the greedy block idea.

Equivalent exact model · O(n²) time · O(n²) space

Safe nonnegative block greedy

Try to delete the shortest left block whose every intermediate remainder is safe and whose centered total is nonnegative. If impossible, try the right. Commit only complete blocks and keep the deletion order.

Exact strategy; naïve scans can be quadratic · O(n²) with repeated rescans time · O(n) space

Amortized block processing

Implement the same strategy with moving endpoints and accumulated block information so scans are not restarted from scratch. Each chamber participates in constant amortized work. The included iterative jury implementation is the complete reference; use the interval DP to stress-test your own optimized version.

Recommended advanced implementation · O(n) with retained scan work time · O(n) space

Boundary checks

A locally removable single endpoint is not necessarily a safe greedy commitment. Track the entire safe block. Reverse the removal order for the required answer. Products n·sum can exceed signed 64-bit: use __int128 for centered sums/comparisons.
