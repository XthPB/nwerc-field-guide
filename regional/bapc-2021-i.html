Greedy, sorting and search · BAPC 2021-I

Implementation Irregularities

Infer the minimum number of computers needed to perform given amounts of work by their observed solve times. Work on one problem may use multiple computers simultaneously.

The observation

Sort solved problems by deadline. For every prefix, cumulative work W must satisfy W≤C·deadline. Therefore C=max ceil(W/deadline).

Why it works

Necessity follows from total available computer time. Sufficiency follows by processing work in earliest-deadline order using the full capacity C, since jobs are divisible and can be worked on in parallel; every prefix then finishes by its deadline. The parallel-work assumption is essential.

From a small instance to the contest constraints

Try computer counts

For each candidate capacity, test all deadline-prefix constraints. Correct, but directly solving the inequalities is better.

Baseline · O(Cn) after sorting time · O(n) space

Simulate divisible work in deadline order

For a fixed C, each job consumes work/C time. Check deadlines. Floating-point simulation is less robust than comparing integer cumulative work.

Alternative explanation · O(n log n) time · O(n) space

Binary search the capacity

Feasibility is monotone: more computers cannot hurt. Binary search with integer prefix checks.

Accepted alternative · O(n log n+n log U) time · O(n) space

Maximum prefix density

Each inequality gives a lower bound on C; take their maximum in one scan.

Recommended · O(n log n) time · O(n) space

Equal-deadline aggregation

Combine work with the same deadline before checking the bound. This exposes that only the final prefix at a shared deadline can be strongest.

Implementation refinement · O(n log n), or O(n+U) for small deadline range time · O(n) space

Boundary checks

Ignore unsolved problems with time −1. Use integer ceiling (W+s−1)/s and 64-bit sums. This formula would not generally solve non-preemptive scheduling or jobs that can use only one computer at a time.
