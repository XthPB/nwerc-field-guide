Imperfect Imperial Units

Answer conversions between named units given equations such as 1 foot = 12 inches. Conversion paths are unique when they exist.

The observation

Make a weighted undirected forest: u→v has multiplier r and v→u has multiplier 1/r. A path product converts quantities. Alternatively assign every unit a potential relative to its component root.

Why it works

Let pot[v] be the factor converting one root unit to units v. Along edge u→v of multiplier r set pot[v]=pot[u]r. Then an amount a in u is a·pot[v]/pot[u] in v. Different components cannot be converted. The unique-path guarantee removes consistency concerns.

From a small instance to the contest constraints

DFS for each query

There are only 100 equations. Follow the unique path, multiplying ratios; return impossible if no path exists.

Simple accepted solution · O(q(V+E)) time · O(V+E) space

Precompute all roots

Run one traversal from each unit and store all known conversions. This exchanges memory for constant-time queries.

Alternative · O(V(V+E)+q) time · O(V²) space

Multiplicative Floyd–Warshall

Replace addition of distances with multiplication of ratios. Because paths are consistent and unique, any known route gives the answer; this is not a shortest-path optimisation.

Dense-graph perspective · O(V³+q) time · O(V²) space

Component potentials

One traversal per component is enough. Store component IDs and root-to-unit factors, then answer with one division.

Recommended reusable pattern · O(V+E+q) time · O(V+E) space

Weighted disjoint-set union

If equations arrive online, store the conversion ratio to each DSU parent. Path compression multiplies ratios. Union must set the new root ratio so the new equation holds; derive its direction carefully.

Online extension · O((E+q) α(V)) amortised time · O(V) space

Boundary checks

The direction of the ratio is easy to reverse: test foot→inch and inch→foot. Do not use an integer type for multipliers. All query units are defined, but they may be in different components.
