Number theory and algebra · BAPC 2022-G

Grinding Gravel

You have stones of known integer weights. You can cut stones and combine pieces into piles. Every finished pile must have exactly the target weight k. How few cuts suffice to distribute all the material?

The observation

If a group of stones has total weight divisible by k, concatenate its material and cut at every k units. It needs groupWeight/k−1 cuts. Thus minimise cuts by maximising the number of disjoint zero-sum groups of residues modulo k.

Why it works

A residue-zero stone can be its own group. A complementary pair r,k−r can also be removed greedily: if its stones were in different optimal groups, extract the pair and merge the two remainders, preserving the group count. Afterwards at most one residue from each complementary pair remains. A count-vector DP maximises zero-sum prefix boundaries in a permutation; those boundaries are precisely a partition into zero-sum groups.

From a small instance to the contest constraints

Enumerate set partitions

Group the stones in every way, retain groups with sum divisible by k, and maximise their count. This tests the reduction but is far too expensive.

Small-instance oracle · Exponential (Bell numbers) time · O(n) space

Subset partition DP

For each remaining mask, choose a zero-sum submask containing a fixed bit. Fixing a bit avoids counting permutations of the same groups.

Exact for small n · O(3^n) time · O(2^n) space

DP on every residue count

Identical residues are interchangeable, so a frequency vector replaces individual stones. Yet seven balanced counts can still create too many states. State compression alone is not the end of the analysis.

Correct but too large without reduction · O(k∏(c_r+1)) time · O(∏(c_r+1)) space

Greedy cancellation plus count DP

Remove zeros and complementary pairs first, then memoise the recurrence on the surviving counts. Each step removes one stone; add one exactly when the current sum is a multiple of k.

Recommended · O(n + d∏(c_i+1)), d≤4 time · O(∏(c_i+1)) space

Mixed-radix bottom-up DP

Flatten the small count grid into one vector. Every predecessor decreases one digit, so increasing mixed-radix index is a topological order. This avoids hash overhead and recursion.

Implementation refinement · Same state bound time · O(∏(c_i+1)) space

Boundary checks

The objective uses the original total weight divided by k; only grouping uses residues. Handle k=1 and the self-complement k/2. After removing pairs the k=8 case has at most three unrestricted counts plus at most one stone of residue 4.
