Games and interactive reasoning · BAPC 2021-G

Gyrating Glyphs

A calculator hides a row of plus and multiplication signs. You can supply the operands and see only the final value, computed left to right modulo a known prime. Recover every hidden sign within the query budget.

The observation

Encode a block of 15 operators into one response. Choose query operands for which all 2^15 operator patterns yield distinct results; verify this property locally before sending the query. Recover blocks from right to left.

Why it works

An all-zero unknown prefix evaluates to zero regardless of its operators. In the already known suffix, supply 0 for + and 1 for × so the block result passes through unchanged. An injective locally checked lookup table then identifies the block uniquely. At most ceil(n/15)≤1334 queries are needed.

From a small instance to the contest constraints

Recover one operator per query

Neutralise known operators and probe one unknown operator at a time. The idea is correct but needs far more than 1400 queries.

Budget failure · O(n) queries and O(n²) printed operands time · O(n) space

Random block fingerprints without checks

Map every pattern to a residue for a random operand vector. Collisions can map several operator strings to the same reply and silently corrupt reconstruction.

Unsafe shortcut · O(2^b b) preprocessing time · O(2^b) space

Verified random codebook

Generate operands, enumerate all patterns, and restart if any evaluation collides. Once found, decoding is exact. Randomness is used to find a certificate, not to guess the answer.

Recommended core · Expected repeated O(2^b b), b=15 time · O(2^b) space

Enumerate the codebook as a binary tree

Each prefix result branches into +q and ×q. DFS shares prefix calculations instead of reevaluating every full pattern from scratch.

Preprocessing refinement · O(2^b) arithmetic per trial time · O(2^b) space

Block isolation and protocol engineering

Work right-to-left. Handle the first partial block with its own injective table. The number of values printed can dominate the local arithmetic, so use buffered output followed by one flush per query.

Complete strategy · ceil(n/b) queries; O(n²/b) output size time · O(n+2^b) space

Boundary checks

Random operands alone do not guarantee unique responses: explicitly reject codebooks with collisions. Query output contains n+1 operands and must follow the protocol exactly. Offline random trials affect preprocessing time, not the query count; flush each query.
