Greedy, sorting and search · BAPC 2023-A

APT Upgrade

Given package sizes, m completed downloads, and capacity for k simultaneous downloads, find the maximum possible percentage of total bytes downloaded. A package can be at 100% without yet being marked finished.

The observation

At most m+k packages can contribute downloaded bytes. Give those slots to the largest packages.

Why it works

If a chosen package is smaller than an unchosen one, swapping them cannot reduce downloaded bytes. Repeating exchanges yields the largest min(n,m+k) sizes. Those packages can all be fully downloaded, with at most k still reported as underway, so the upper bound is achievable.

From a small instance to the contest constraints

Enumerate contributing subsets

Choose up to m+k packages and maximize their total size.

Tiny n only · O(2^n·n) time · O(n) space

Repeatedly select the largest remaining

Find and mark the largest unchosen size on each iteration. This establishes the greedy choice before selecting a faster data structure.

Valid baseline · O(n·min(n,m+k)) time · O(n) space

Sort descending

Sort once and take the prefix. This is easy to implement and audit.

Recommended · O(n log n) time · O(n) space

Maintain a min-heap of selected sizes

Keep only the largest c elements seen so far. This is useful if the input is streamed or n grows far beyond memory.

Streaming alternative · O(n log c), c=min(n,m+k) time · O(c) space

Partition with nth_element

Partition the largest c values without fully sorting them, then sum. Handle c=n separately rather than using an out-of-range nth position.

Advanced selection alternative · Average O(n) time · O(n) space

Boundary checks

Clamp m+k to n. Sum sizes in 64-bit. The problem permits 100% downloaded but not marked complete; do not arbitrarily subtract epsilon.
