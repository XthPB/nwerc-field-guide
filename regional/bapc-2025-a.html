Probability, expectation and randomization · BAPC 2025-A

Accidental Arithmetic

A calculator reads a long sequence of digits. After each digit it independently inserts a plus sign with probability 0.45, a minus sign with probability 0.45, or nothing with probability 0.10. Digits left together form one number. Ignoring a final operator, what is the expected value of the expression?

The observation

Pair each outcome after the first inserted operator with the outcome obtained by flipping that operator. The suffix cancels in expectation; only the unsigned first number survives.

Why it works

Let d be the digit count and P_k the integer represented by its first k digits. The first term has length k<d with probability 0.9·0.1^(k−1), and length d with probability 0.1^(d−1). Summing these weighted prefixes gives the expectation. For digit a_k (one-based), its total coefficient is 10^(1−k)·[1+0.9(d−k)]. The formula is linear in the digits, so it can be accumulated without constructing a 1,000-digit integer.

From a small instance to the contest constraints

Enumerate the calculator outcomes

Branch on the three possibilities at every gap, evaluate each resulting expression, and weight it by its probability. This is an excellent oracle for short inputs because it follows the experiment literally.

Small inputs only · O(d·3^d) time · O(d) space

Monte Carlo simulation

Sample R expressions and average their values. This makes the expectation tangible, but a few rare long concatenations dominate variance. It cannot promise the required 10^-6 accuracy; use it to explore tiny examples, not as a contest solution.

Approximation; no precision guarantee · O(Rd) time · O(d) space

Condition on the first operator

For every possible prefix length, build the scaled prefix a1.a2...ak rather than P_k. Add 0.9 times each proper prefix and the whole scaled number once. Rebuilding each prefix is quadratic but easily fits 1,000 digits.

Exact formula; efficient · O(d²) time · O(d) space

Reuse the scaled prefix

The next scaled prefix adds just one decimal-place contribution. This is the same expectation formula with repeated work removed. For 1234, it computes 0.9(1+1.2+1.23)+1.234=4.321.

Recommended · O(d) time · O(1) beyond input space

Linearity by individual digit

Collect the coefficient of each digit across all prefix cases. This removes even the prefix accumulator and illustrates how changing the summation order can reveal a simpler algorithm. Reading the input remains linear even if negligible tail contributions are truncated.

Alternative; advanced derivation · O(d) time · O(1) beyond input space

Boundary checks

Never parse the input into long long. Avoid computing an enormous prefix and multiplying it by a tiny probability: overflow can happen first. The alternative digit coefficient on the jury slide has an off-by-one; use d−k, not d−k+1. For n=1 the answer must be 1.
