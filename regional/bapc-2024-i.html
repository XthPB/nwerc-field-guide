Advanced DP across subjects · BAPC 2024-I

Interrail Pass

Pay for trips on specified days using either individual fares or passes limited by both a validity period and a number of covered travel days. Minimize total cost.

The observation

Index the DP by trips, not calendar days. Think backwards: if a pass covers the last trip of a prefix, how far back can that pass cover?

Why it works

Let dp[i] be the least cost for the first i trips. Pay fare_i plus dp[i−1], or use pass j ending at trip i. Its covered suffix is limited both by d_j trips and p_j days, so the uncovered prefix ends at max(i−d_j, prev(t_i−p_j)), clamped to zero. Any optimum has a final payment covering a suffix; removing it leaves an optimal smaller prefix. Conversely each transition buys a valid coverage block.

From a small instance to the contest constraints

Enumerate payment choices

Recursively choose a single fare or each pass for the remaining trips. Identical remaining prefixes are solved repeatedly.

Tiny inputs only · Exponential in n time · O(n) space

Memoization with linear boundary scans

Cache dp[i], but scan backwards to find each pass’s time boundary. This isolates DP correctness before optimizing predecessor lookup.

Intermediate exact baseline · O(n²k) time · O(n) space

DP with binary search

For each pass and trip, upper_bound finds the last trip outside the valid time interval. Combine it with the trip-count bound.

Recommended · O(nk log n) time · O(n) space

One moving pointer per pass

As i increases, each pass’s first coverable trip can only move forward. Advance its time pointer instead of repeating binary searches.

Faster alternative · O(nk) time · O(n+k) space

Shortest paths on a prefix DAG

Treat prefix indices as vertices. Buying a fare or pass creates a forward edge from the uncovered prefix to the covered prefix, weighted by cost. Topological shortest paths are exactly the DP; no Dijkstra heap is needed.

Alternative model · O(nk) once boundaries are known time · O(nk) explicit, O(n) implicit space

Boundary checks

The pass duration and trip count are simultaneous constraints. Carefully define inclusive days: trips with t≤t_i−p_j are outside a pass covering p_j days ending today. Use 64-bit money and include dp[0]=0.
