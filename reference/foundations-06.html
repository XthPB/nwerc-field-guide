Knapsack, subsequences and interval DP

A backpack has a weight limit, and each available item has a weight and a value. Pick each item at most once to maximize the total value you carry. Then compare the decision you make here with choosing an ordered subsequence or merging adjacent piles.

One template, different dependency directions

In 0/1 knapsack, item i may be used once. dp[w] stores the best value at capacity w. Iterate w downward so dp[w-weight] still belongs to the previous item layer.

for(auto [weight,value]:items)
    for(int w=W;w>=weight;--w)
        dp[w]=max(dp[w],dp[w-weight]+value);

For unlimited copies, iterate upward: using an updated state deliberately permits another copy. For exact weight, initialise dp[0]=0 and all other entries to −∞; for “at most W”, all-zero initialisation can be valid when taking nothing is allowed. Those initialisations solve different problems.

Change which quantity is the state

If capacity is 10^9 but the sum of values is 10000, store minimum weight for each total value. If both are huge but there are at most 40 items, meet in the middle. If weights have a small modulus or only a few distinct types, count-vector DP may help. Constraints are clues about which dimension can be enumerated.

Longest increasing subsequence

The O(n²) DP is dp[i]=1+max(dp[j]) over j<i with a[j]<a[i]. The O(n log n) method stores the smallest possible final value of an increasing subsequence of each length. A smaller tail preserves more future options.

vector<long long> tail;
for(long long x:a) {
    auto it=lower_bound(tail.begin(),tail.end(),x);
    if(it==tail.end()) tail.push_back(x); else *it=x;
}

For nondecreasing subsequences, use upper_bound. The tails array is not necessarily the subsequence itself; reconstruction needs predecessor indices.

LCS: two advancing boundaries

For strings a and b, dp[i][j] is the longest common subsequence of their prefixes. Equal final characters can extend dp[i−1][j−1]; otherwise drop one final character. Time is O(nm). Two rows give lengths in O(min(n,m)) memory; Hirschberg’s divide-and-conquer reconstructs an LCS with linear working memory and O(nm) time.

Evolutionary Excerpt relaxes optimality and promises random strings. That allows local block LCS or a banded DP. Do not apply those shortcuts to arbitrary LCS problems.

Interval DP: choose the final split

When a solution acts on a contiguous interval, try dp[l][r]. For matrix-chain multiplication, splitting at k yields two smaller intervals plus a merge cost. Process by increasing length:

for(int len=2;len<=n;len++) for(int l=0;l+len<=n;l++) {
    int r=l+len;
    for(int k=l+1;k<r;k++)
        dp[l][r]=min(dp[l][r],dp[l][k]+dp[k][r]+mergeCost(l,k,r));
}

O(n³) is the baseline. Knuth or divide-and-conquer optimisation requires extra structure; a split recurrence alone does not justify either.

Checkpoint: what happens if you run 0/1 knapsack upward?

The same item can feed its own later states, so you silently solve an unbounded variant. With one item of weight 2 and value 3, capacity 4 would incorrectly get value 6.
