Profile DP and digit DP: remember the boundary

Why a narrow grid is manageable

A 1000×8 board has far too many cell subsets, but only a small frontier between processed and unprocessed cells. If future interactions cross only that frontier, remember the frontier configuration and forget the rest.

For domino tilings processed row by row, bit j means cell j is already occupied by a vertical domino from the previous row. A transition fills the remaining cells with horizontal dominoes or starts vertical ones for the next row. The state count is 2^width, not 2^(area).

void fillRow(int col,int incoming,int outgoing,long long ways) {
    if(col==width) { next[outgoing]+=ways; return; }
    if(incoming>>col&1) { fillRow(col+1,incoming,outgoing,ways); return; }
    fillRow(col+1,incoming,outgoing|(1<<col),ways); // vertical
    if(col+1<width && !(incoming>>(col+1)&1))
        fillRow(col+2,incoming,outgoing,ways);      // horizontal
}

At the final row, forbid new vertical dominoes. Blocked cells require extra checks. The code is a transition pattern, not a complete tiling solver for every board convention.

Cangaroo adds a physical boundary condition

A band placement is a set of nonadjacent can starts. Its occupied columns are mask | (mask<<1). The next band must cover its marked cells and every upper can must overlap support below. The lower arrangement matters only through this occupancy boundary, which is why profile DP works.

With width m, valid placements are Fibonacci-sized: either the first position is unused, or a can occupies the next two columns. This gives S(m)=S(m−1)+S(m−2). Precompute compatibility between S states, then process rows in O(height·S²), with O(S) rolling values.

Connectivity profiles: the advanced jump

If the problem asks for a single connected path or component, occupied bits are insufficient. You must record which frontier cells are connected through the processed region. Canonically relabel components, for example [4,4,7,0]→[1,1,2,0], so equivalent histories share a state. For planar noncrossing paths, bracket encodings can reduce the state family further. This is often called plug DP.

The lesson is not to memorise a huge transition template. Ask what a future cell needs to know about the past: occupancy, parity, degree, connectivity, or several of these.

Digit DP is also frontier DP

To count integers ≤N with a digit property, process digits left to right. Typical state: position, whether the prefix is still tight to N, whether the number has started, and the property state (sum modulo k, automaton node, used-digit mask).

int limit=tight ? digits[pos] : 9;
for(int d=0;d<=limit;d++)
    addState(pos+1,tight && d==limit,started || d!=0,
             updateProperty(property,d,started));

Leading zeros are not necessarily real digits. Counting numbers with no repeated digits, for example, must not mark zero as used before the number starts. Count a range [L,R] by count(R)-count(L-1).

Checkpoint: why can an occupancy-only profile fail for a Hamiltonian cycle?

Two partial paths can occupy the same frontier cells but connect them differently behind the frontier. Closing one pairing may create a premature cycle; the other may extend into a valid final cycle. The future can distinguish those histories, so the state must too.
