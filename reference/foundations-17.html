Range queries: prefix sums to segment trees

Choose the operation before the structure

Need First tool to consider
Static range sum Prefix sums
Point addition and prefix/range sum Fenwick tree
Static range minimum Sparse table

Range update and range query Lazy segment tree, if tags compose
Offline window frequency queries Mo's algorithm

A segment tree is not automatically better than a prefix array. Its value is handling updates or more general associative aggregates.

Fenwick tree: binary-sized prefix pieces

A one-based Fenwick node i stores a suffix of the prefix ending at i, of length i&-i. A prefix query strips the lowest set bit; an update adds that bit to visit all containing nodes.

struct Fenwick {
    int n; vector<long long> bit;
    Fenwick(int n):n(n),bit(n+1){}
    void add(int i,long long x){for(++i;i<=n;i+=i&-i)bit[i]+=x;}
    long long prefix(int r){ // sum of [0,r)
        long long s=0;for(;r;r-=r&-r)s+=bit[r];return s;
    }
    long long sum(int l,int r){return prefix(r)-prefix(l);}
};

Each operation costs O(log n), memory O(n). Difference arrays plus one or two Fenwick trees support range additions with point or range-sum queries. Derive the two-tree formula from weighted prefix contributions rather than memorising offsets.

A segment tree stores a monoid

A monoid is an associative combine operation with an identity. Sum has identity 0, minimum has +∞, maximum has −∞, and matrix product has the identity matrix. Associativity allows intervals to be split and recombined. Commutativity is not required.

// Leaves start at index N, with N a power of two.
auto query(int l,int r) {
    auto left=identity(),right=identity();
    for(l+=N,r+=N;l<r;l/=2,r/=2) {
        if(l&1) left=merge(left,tree[l++]);
        if(r&1) right=merge(tree[--r],right);
    }
    return merge(left,right);
}

The separate left and right accumulators preserve order. This matters for strings, matrices and function composition. Build time is O(n); point updates and queries are O(log n).

Store enough information to merge

For maximum subarray sum, each node needs total sum, best prefix, best suffix and best subarray. Merge two nodes by considering a best subarray wholly left, wholly right, or crossing the boundary as left suffix + right prefix. Storing only the best subarray loses information needed by the parent.

This mirrors DP state design: a segment summary must expose everything the outside world can observe across its boundary.

Sparse tables

For static idempotent operations such as min, build answers for intervals of length 2^k. A query uses two possibly overlapping blocks of length 2^floor(log length); overlap is harmless because min(x,x)=x. O(n log n) preprocessing and O(1) queries. This overlapping trick does not work for sums; it would count overlap twice.

Checkpoint: can an ordinary Fenwick tree answer arbitrary range minimum after arbitrary updates?

Not with the standard subtraction trick: minimum has no inverse. Special restricted-update variants exist, but a segment tree is the general tool for arbitrary point changes and range minima.
