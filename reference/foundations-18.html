Lazy propagation and persistent structures

A lazy tag is a promise about every element

A range addition by x changes a segment sum by x·length. Instead of visiting every leaf, update the stored sum and leave a tag saying every descendant still owes this addition. Push the tag before inspecting or modifying only part of the segment.

void apply(int node,int length,long long x) {
    sum[node]+=x*length;
    lazy[node]+=x;
}
void push(int node,int leftLen,int rightLen) {
    apply(node*2,leftLen,lazy[node]);
    apply(node*2+1,rightLen,lazy[node]);
    lazy[node]=0;
}

The operation costs O(log n) per contiguous range update/query because only O(log n) boundary nodes are partially visited.

Composition order is the difficult part

For range affine updates x↦a x+b, a sum node of length L changes to a·sum+bL. If an old pending tag is (a₁,b₁) and a newer update is (a₂,b₂), the combined tag is:

new ∘ old = (a₂a₁, a₂b₁+b₂)

Set-to-c is (0,c); add-d is (1,d). Set to 5 then add 2 gives 7, while add 2 then set to 5 gives 5. Reversing composition order is a real correctness bug, even though addition-only tests may never reveal it.

The structure needs three compatible operations: merge summaries, apply a tag to a summary, and compose tags. Applying a tag to a merged segment must agree with applying it to both children then merging.

When ordinary lazy propagation fails

Range chmin(x) with range sums cannot be represented using only sum and length: [1,9] and [5,5] have the same sum but react differently to chmin(6). Segment tree beats stores extra extrema and counts, applies updates cheaply only under certain conditions, and descends otherwise. Its complexity requires a separate amortised proof. It is a specialist tool, not a generic tag trick.

Persistence: remember old versions

A persistent segment tree copies only nodes on an updated root-to-leaf path. Unchanged subtrees are shared. A point update creates O(log n) nodes and returns a new root; old roots remain valid.

For static range k-th queries, build one frequency-tree version per prefix of the array after coordinate compression. Subtract counts between roots r and l to represent subarray [l,r). At each level, compare k with the difference of left-child counts, then descend left or right. Query time O(log σ), total nodes O(n log σ).

int kth(int rootL,int rootR,int k) {
    int leftCount=count[left[rootR]]-count[left[rootL]];
    if(isLeaf(rootR)) return coordinate(rootR);
    if(k<=leftCount) return kth(left[rootL],left[rootR],k);
    return kth(right[rootL],right[rootR],k-leftCount);
}

This subtraction is valid because counts are additive. You cannot subtract arbitrary minimum-tree roots to get a range minimum.

Implicit trees and treaps

An implicit segment tree allocates nodes only for visited portions of a huge coordinate domain. A treap uses random priorities to maintain expected logarithmic height and supports split/merge. An implicit treap indexes sequence positions and can support reversal or cut-and-paste with lazy tags. These are broader ICPC preparation; the five-year corpus does not imply every one will appear next year.

Checkpoint: what must a lazy reversal tag do to a noncommutative summary?

Reverse the order-dependent aggregate, often by swapping stored forward and backward summaries and swapping children. Merely setting a Boolean tag while leaving the aggregate unchanged is insufficient.
