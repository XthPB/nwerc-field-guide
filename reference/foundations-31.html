An advanced ICPC algorithm map

Learn by the obstruction each tool removes

A long algorithm list is useful only if you can recognise what problem blocks progress. Use this map to diagnose that obstruction, then return to the linked theory chapters and implement the technique on a small exercise.

Obstruction in your current model Technique to investigate Essential condition
Too many equivalent histories DP state compression, Pareto pruning Same future behaviour or proven dominance
Quadratic minimum over old states Deque, segment tree, CHT/Li Chao Window monotonicity or line-form transition
Cyclic dependencies SCC condensation Component can be summarised correctly
Many subtree/path queries Euler tour, LCA, HLD Rooted tree structure
Dynamic connectivity with deletions Reverse time, rollback DSU Offline lifetime information
Global one-to-one assignment Matching, Hungarian, flow Correct compatibility/capacity model
Huge step count, small state Binary lifting, matrix exponentiation Repeatable deterministic/linear transition
Many substring comparisons Suffix array/LCP, suffix automaton Exact substring structure
Polynomial-size counting convolution FFT/NTT Coefficient and modulus bounds
Small separator or narrow width Profile/plug DP, treewidth DP Boundary state captures interactions
Continuous degrees of freedom Tight-constraint enumeration Valid perturbation/exchange lemma

Euler tours are not Hamiltonian paths

An Euler trail uses every edge exactly once; a Hamiltonian path visits every vertex exactly once. Hierholzer's algorithm constructs an Euler trail in O(V+E) after degree and connectivity conditions are checked. Store edge IDs and mark each edge once, including parallel edges. Reverse the vertex sequence produced by backtracking.

For an undirected graph, nonzero-degree vertices must be connected and the number of odd-degree vertices must be zero or two. For directed graphs, in/out balance and suitable connectivity conditions replace parity. These are separate from the distance-three construction in Hamiltooonian Hike.

Advanced graph models

Minimum-cost flow handles capacities plus costs. 2-SAT handles Boolean clauses of size two. General SAT, general longest simple path, and arbitrary set cover do not become easy just because n is large; look for a special parameter, tree structure, planarity, bounded degree, or approximation only if the statement allows it.

Treewidth formalises “small boundary”: a bag of k vertices can support exponential-in-k DP while the whole graph is large. Planar separators and centroid decomposition are related divide-and-conquer ideas, but their invariants differ.

Advanced geometry and optimisation

Half-plane intersection, rotating calipers, Minkowski sums and minimum enclosing circles are useful after mastering orientation, hulls and degeneracies. Randomised incremental minimum enclosing circle has expected linear behaviour with a constant-size boundary certificate. Delaunay/Voronoi structures are powerful but implementation-heavy; a local contest may offer a simpler spatial or distribution-based route.

For optimisation, Lagrangian relaxation (often called the aliens trick in CP) introduces a penalty to trade count against cost. Recovering an exact constrained optimum needs a justified convexity/duality argument and tie handling. Do not binary-search a penalty and assume every desired count will appear.

Prioritise depth over collecting templates

First make BFS, Dijkstra, SCC, Fenwick, segment tree, knapsack, tree DP and modular arithmetic dependable. Then add matching/flow, rerooting, bitmask/profile DP, suffix structures and DP optimisation. Specialist topics are a final layer.

Checkpoint: what should you do when you recognise three possible algorithms?

Write the state/graph each would use, its exact complexity under the bounds, and the missing proof condition. Choose the simplest candidate whose conditions you can establish. Familiarity alone is not evidence that a technique applies.
