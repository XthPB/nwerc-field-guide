Optimising DP without guessing

You reach position i by extending one allowed earlier position j and paying a fee for i. The eligible j form a consecutive interval, and you want the cheapest total cost. Looking at every j for every i is too slow. Read that transition closely before choosing a faster data structure.

First write the slow recurrence

Suppose dp[i]=cost[i]+min(dp[j]) for L[i]≤j<i. The recurrence tells you what operation to accelerate: a range minimum. If L[i] moves only forward, use a monotonic deque; for arbitrary ranges, a segment tree. Optimisation starts from the transition, not a favourite data structure.

In Museum Visit, derive L[i] from intervals that must already have been hit before choosing i. Only then choose a queue. Getting the boundary wrong makes an extremely fast incorrect algorithm.

Remove a dimension with dominance

In Exam Study Planning, for each number passed retain the greatest spare time. A state with less spare time and the same passed count is dominated. More generally, maintain a Pareto frontier: state A dominates B only if A is at least as good in every future-relevant resource and strictly better in one.

Do not prune merely because one state has a lower current cost: it may also have used more fuel, lost a special action, or reached a different incoming direction.

Divide-and-conquer optimisation

Consider layered DP:

dp[t][i] = min over j<i {dp[t−1][j] + C(j,i)}

If an optimal split opt[t][i] can be chosen nondecreasing in i, compute the middle endpoint first. Its split restricts the candidate ranges for the left and right halves. With O(1) cost queries, a standard layer costs O(n log n) instead of O(n²). Prove the monotone-opt property, often from a Monge/quadrangle inequality; do not infer it from a few examples.

void compute(int l,int r,int optL,int optR) {
    if(l>r) return;
    int mid=(l+r)/2, best=-1;
    for(int j=optL;j<=min(mid-1,optR);j++)
        if(improves(previous[j]+cost(j,mid))) best=j;
    compute(l,mid-1,optL,best);
    compute(mid+1,r,best,optR);
}

The snippet omits bookkeeping to keep attention on the search ranges; the empty-prefix bases still need explicit treatment.

Convex hull trick and Li Chao trees

If expansion gives dp[i]=constant(i)+min_j(m_j x_i+b_j), every old state is a line. Query the lower envelope. With sorted slopes and sorted x queries, a deque hull can be linear after insertion; arbitrary order often suggests a Li Chao tree, typically O(log U) per operation on a bounded coordinate domain.

Example: (x_i-x_j)²+dp[j] expands to x_i² + (-2x_j)x_i + (x_j²+dp[j]). The square is not a reason to use floating-point geometry: line comparisons can often use 128-bit integer products.

Knuth and balanced partitions

Knuth optimisation applies to certain interval DPs with suitable cost inequalities and split bounds opt[l][r−1]≤opt[l][r]≤opt[l+1][r], reducing O(n³) to O(n²). It is distinct from divide-and-conquer layered DP.

Sometimes algebra beats both. Convex block costs imply balanced block lengths for a fixed number of blocks. Crashing Competition Computer then has an O(c) derived solution after its O(c²) baseline.

Checkpoint: what evidence justifies replacing a quadratic transition with a deque?

You need a moving feasible interval whose endpoints evolve monotonically, and a dominance rule independent of future queries. A minimum over arbitrary subsets or a query-dependent comparison does not meet those conditions.
