Tree DP and the art of merging children

You have a tree with a reward at each vertex. Choose vertices of maximum total reward, with the restriction that two neighbors cannot both be chosen. When you cut the edge from a child to its parent, what does the parent need to know about the child’s choices?

A tree gives you independence after a cut

Root the tree. Removing an edge separates a child's subtree from everything else. Once you describe how the child interacts through its parent boundary, different child subtrees can often be combined independently.

For maximum-weight independent set, keep two states: take[u] and skip[u]. Taking u forces skipping every child; skipping u permits the better choice for each child. That is a constant-size message across each edge.

take[u]=weight[u]; skip[u]=0;
for(int v:children[u]) {
    take[u]+=skip[v];
    skip[u]+=max(take[v],skip[v]);
}

Negative weights are fine when the empty set is allowed. If at least one vertex must be chosen, state that extra condition explicitly.

Connected subsets: why the root condition matters

For Jungle Job, let dp[u][k] count connected k-vertex subsets inside u's subtree that contain u. Start with dp[u][1]=1. For each child v, either select nothing from its subtree, or select a connected subset containing v. If you chose vertices below v without v, the chosen set would disconnect.

new[i+j] += dp[u][i] · dp[v][j] for j≥1
new[i] += dp[u][i] for choosing nothing from v
vector<long long> next(sizeU+sizeV+1,0);
for(int i=1;i<=sizeU;i++) {
    next[i]=(next[i]+dpU[i])%MOD;
    for(int j=1;j<=sizeV;j++)
        next[i+j]=(next[i+j]+dpU[i]*dpV[j])%MOD;
}

Use a fresh array while merging a child; otherwise you may reuse that same child several times. Modulo multiplication may need 128-bit arithmetic if the modulus is large.

Count each object once

Every nonempty connected subset has a unique highest vertex in the rooted tree. Sum dp[u][k] over all u to count all connected k-subsets. This is the missing step in many first attempts: a root-conditioned DP does not automatically count objects that exclude the global root.

Why the knapsack can be O(n²)

A naive “n nodes times n² merging” analysis says O(n³). A tighter analysis charges multiplication pairs to vertices in different merged portions. Each pair meets at a unique lowest common ancestor/merge, giving O(n²) total pair work when loops use actual subtree sizes. Allocating or scanning full length-n arrays at every merge can lose that bound.

Generating functions make the same recurrence visible

Write P_u(x)=Σ dp[u][k]x^k. Then P_u(x)=x∏(1+P_v(x)). Coefficient multiplication is the child convolution; the 1 means skip that child. FFT/NTT may accelerate some large convolutions, but a global speed-up needs analysis of the whole merge tree and polynomial sizes. It is not automatically near-linear.

Beyond two states

Common boundary information includes whether u is selected, degree used at u, distance to a marked vertex, parity, or the number of chosen vertices. Write the legal combinations as a small table before coding. If the state must record arbitrary connectivity among many boundary vertices, you have moved toward treewidth/profile DP.

Checkpoint: why is multiplying counts valid for two child choices?

The child subtrees are disjoint and, after fixing the parent boundary condition, their choices do not constrain one another. Each pair of child configurations yields one distinct combined configuration. If cross-child constraints exist, they must be represented in the merge state.
