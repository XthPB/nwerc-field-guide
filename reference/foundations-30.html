Numerical reasoning and robust computation

Error is part of the specification

An absolute tolerance controls |answer−true|; a relative tolerance controls error compared with the magnitude of the true value. Near zero, relative error alone can be meaningless. Read the judge's stated condition and print enough significant digits; extra digits do not repair a wrong formula.

Use exact integers for combinatorial decisions whenever possible, then convert once for the final real-valued result. Bellevue compares slopes by cross products and applies atan2 only to the winner. Knowing the Clock uses modular arithmetic rather than simulating approximate angles.

Avoid overflow before conversion

long double energy=0;
for(long long a:samples) energy+=(long double)a*a;
long double factor=energy==0 ? 0 : sqrtl((long double)n*target/energy);

Casting after a*a is too late if integer multiplication overflows. For extremely large real amplitudes, divide by the maximum absolute amplitude before squaring, then scale back algebraically. This is a general numerical technique, although Equalising Audio's bounds permit ordinary 64-bit sums.

Cancellation and stable forms

Subtracting two nearly equal large numbers can lose significant digits. If solving x²+bx+c=0, the textbook quadratic formula can suffer cancellation for one root; compute the stable root with a sign-aware formula and obtain the other from the product c. In geometric constructions, prefer a parameterisation whose values remain on the intended segment.

Use hypotl(x,y) for lengths when overflow/underflow is a concern. Use atan2(y,x) rather than atan(y/x) when quadrants or zero denominators matter.

Exponential values need bounds

Crashing Competition Computer's expected unsaved-block cost grows geometrically. Some values can overflow floating point although the optimum is modest. A known feasible strategy provides an upper bound U. Any nonnegative-cost candidate already exceeding U can be capped at U or safely skipped. This is a proof-backed numerical guard, not arbitrary truncation.

Probability products may underflow. Taking logs converts products to sums, but remember that probability zero maps to −∞ and comparisons reverse if you negate logs. If the answer itself must be a probability, exponentiate only at the end when appropriate.

Binary-search error contracts

For a monotone continuous predicate with bracket width W, I bisections reduce width to W/2^I. Pick I based on the original bound and required precision. A fixed 100 iterations is often ample for contest-scale long doubles, but state what it guarantees for the domain.

Never query an interactive sentinel outside the valid coordinate range. A logical upper bound h+1 can mean “known sky” without being an allowed query.

Test numerical boundaries deliberately

Use zero input, zero target, equal values, near-tangent geometry, the exact threshold, just above and below it, and the largest magnitudes. Compare independent formulations: energy before/after scaling, exact cross products versus angle ordering, DP versus a closed-form optimisation.

Checkpoint: does long double make all geometry predicates safe?

No. Precision is finite and platform-dependent. Near-zero cross products or nearly equal distances can still be ambiguous. Exact integer predicates with a sufficiently wide type are stronger when the input permits them.
