Range queries and sweeps · Foundations

Offline queries, square-root decomposition and small-to-large

A fixed array receives many requests such as counting the distinct values inside different intervals. You have the whole batch before you must output answers in the original order. Decide whether reordering work, moving endpoints or merging smaller collections can save repeated scans.

Offline means you may choose the order

If all queries are known before answering, sort them into an order that makes updates cheap, then restore original output order. Example: answer “how many array values ≤x lie in [l,r)?” Sort array positions by value and queries by x. Activate eligible positions in a Fenwick tree; each query becomes a range sum. Time O((n+q) log n).

The same sweep principle powers threshold connectivity and geometric dominance counting. If queries depend on previous answers, this reordering may be forbidden.

Heavy and light cases

Suppose sets contain M total memberships. Choose threshold B. There are at most M/B heavy sets, because each contains at least B memberships. Compare heavy sets broadly; process light sets by enumerating their pairs.

If the work is roughly M·B + M²/B, balance the terms at B≈√M, giving O(M√M). Duo Detection uses this style to find two collections sharing enough symbols. The threshold comes from algebra, not from “square roots are common in CP.”

for(auto& set:sets) {
    if(set.size()<B) processAllPairs(set);
    else processHeavyAgainstAll(set);
}

Count pair work with the actual bound: Σ smallSize² ≤ B·Σ smallSize ≤ BM. A single giant set is exactly why a uniform pair-enumeration solution can fail.

Mo's algorithm

For static range queries where adding/removing one endpoint is cheap, sort queries by left block and alternating right endpoint. Maintain the current interval and move its ends to match each query. With block size about √n and q≈n, total movement is O(n√n); a more general bound depends on both n and q and the chosen block size.

Good examples: number of distinct values, frequency-based scores, and pair counts. Poor examples: operations where removing an element is hard, or simple sums already answered by prefix arrays.

Small-to-large merging

To merge sets attached to tree subtrees, insert the smaller set into the larger. Every time an element moves, its containing set at least doubles, so it moves O(log n) times. With balanced-tree insertions, total time is often O(n log² n); with suitable hash maps, expected O(n log n).

This is a different technique from DSU union by size even though the doubling proof is similar. “DSU on tree” also refers to a sack-style traversal that keeps a heavy child's frequency data while processing light children.

Rollback over a segment tree of time

An edge active during [l,r) is added to O(log q) time-tree nodes. Traverse the tree, apply each node's edges to a rollback DSU, answer leaf-time queries, and undo before returning. This transforms deletions into scoped insertions. With O(log n) rollback-DSU operations, a typical bound is O((updates·log q)·log n + query work).

CDQ divide and conquer

For three-dimensional dominance or time-ordered updates, split by one coordinate/time dimension, recursively solve each half, then count cross-half effects with a sweep and Fenwick tree. The subtlety is counting only allowed direction pairs, such as earlier updates affecting later queries. Treat equal coordinates consistently.

Checkpoint: why can heavy/light analysis survive one set containing almost every element?

Such a set is expensive individually, but there can be very few of them under a total-membership bound. The method pays for rare large objects differently from numerous small ones.
