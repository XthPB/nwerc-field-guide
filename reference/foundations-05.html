Dynamic programming: design the state first

DP is controlled forgetting

Imagine studying for several exams. Two different histories have reached the same exam, passed the same number of exams, but leave 7 and 12 units of spare time. If future decisions only care about available time, the 7-unit history is dominated. Keep the best resource for each passed count.

A state is a promise about what information from the past the future can observe. “Use DP” is not a state definition. Write a sentence beginning dp[…] means… and include whether it is a minimum, maximum, count, probability or feasibility flag.

Derive a DP in five pieces

  1. State: what makes two histories interchangeable?
  2. Transition: what is the next choice or final choice?
  3. Base: what is true before making any choices?
  4. Order: why are dependencies already computed?
  5. Answer: which states represent finished solutions?

For a minimum-cost partition of a prefix, choose the final block:

dp[i] = min over j<i of {dp[j] + cost(j,i)}
dp[0]=0; unreachable states = +∞

Every valid partition has a unique final cut, so the recurrence is complete. Combining an optimal prefix with a legal final block is feasible, so it never invents a solution. These two directions are the standard induction proof.

Worked example: word break

Dictionary {a, ab, bc} and string abc. A greedy longest first word chooses ab and gets stuck at c. DP keeps all reachable boundaries: 0→1 using a, then 1→3 using bc.

vector<char> can(s.size()+1,false); can[0]=true;
for(int i=0;i<(int)s.size();i++) if(can[i])
    for(const string& w:dictionary)
        if(s.compare(i,w.size(),w)==0) can[i+w.size()]=true;

This version costs the sum of attempted character comparisons. A trie or bounded word lengths can reduce it. The optimisation changes transition discovery, not the state meaning.

DP and shortest paths are the same view in a DAG

Make every state a vertex and every transition an edge. Minimum cost is shortest path; maximum score is longest path; counts add over incoming edges. If a resource always increases, that resource may give a topological order. Boggle Sort advances through columns; Interrail Pass advances through trips.

A cycle changes the problem. Ordinary memoisation cannot solve dp[u] by recursively calling itself through a cycle. You may need Dijkstra, SCC contraction, equations, or a game-theoretic fixed point.

Memory compression is a dependency proof

If layer i only reads layer i−1, keep two arrays. Updating one array in place can be correct or catastrophic depending on iteration order. In Decelerating Jump, decreasing speed and increasing position are part of the proof, not cosmetic loop choices.

Checkpoint: why does “best spare time for each passed count” work, while “maximum passed so far” alone does not?

The number passed does not determine what future exams remain affordable. Spare time affects future choices. Keeping the maximum spare time for a fixed passed count preserves every future opportunity and removes only dominated histories.
