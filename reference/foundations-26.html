Interactive algorithms and query budgets

A judge chooses a secret integer from 1 through 16. You can ask whether it is at most a threshold of your choice. Find the secret in at most four yes-or-no replies, whatever value the judge chose. Which question should come first?

The algorithm includes a conversation protocol

An interactive submission alternates outputs and replies. A correct mathematical strategy can fail because it prints an invalid coordinate, forgets to flush, exceeds the query limit, or continues after the judge reports an error.

int ask(int l,int r) {
    cout<<"? "<<l<<' '<<r<<endl; // endl flushes
    int reply;
    if(!(cin>>reply) || reply==-1) exit(0);
    ++queries; return reply;
}

This is only a protocol pattern. Actual commands, response types, indexing and error signals vary by problem; read the original statement. Never assume every interactive problem uses ? and !.

Count information, not only time

A yes/no answer carries at most one bit. Identifying one of N possibilities therefore needs at least ceil(log2 N) such answers in the worst case. But a modular arithmetic response can carry far more information: Gyrating Glyphs distinguishes 2^15 operator patterns with one carefully designed query.

A query can be valuable because it halves possibilities, reveals a boundary, certifies a candidate, or encodes many unknowns at once. Write a worst-case or probabilistic query bound explicitly.

Monotonicity and boundary finding

Dividing DNA has a monotone interval property. The shortest absent prefix can be found by binary search, but repeating binary search for many segments can violate the total budget. A single scan asks at most n questions. Here the “more advanced” binary-search primitive is less suitable than amortised monotone scanning.

Extraterrestrial Exploration uses sorted values and a concave geometric objective. The best third point lies near the midpoint in value between the extreme choices. Binary search locates that boundary, followed by checking neighbouring candidates.

Divide and conquer for a local peak

For a grid with distinct heights, query a middle row/column separator and take its maximum. If a neighbour is higher, recurse into the corresponding side while retaining a high boundary witness. The separator blocks an escape to the discarded side without first descending, so a local peak remains in the retained region.

A careless implementation that forgets the witness can return a point maximal only within the subrectangle, not in the original grid. King of the Hill is a demanding exercise in keeping a geometric invariant while counting queries.

Encoding and error correction

Faulty Connection is a multi-run communication problem rather than a standard back-and-forth conversation. The sender selects symbols; the receiver sees only survivors. Model the requirement as intersection/uniqueness of codewords, then use finite-field lines. Keep the encoding format and the mathematical code separate so both can be tested.

Build a local interactor

A simulator should validate query syntax, coordinates and count, answer from hidden data, and validate the final claim. Test extreme hidden instances and adversarial ties where allowed. Seed random tests for reproducibility and record the maximum queries observed; that is evidence, not a universal proof.

Checkpoint: why is printing debug output to stdout dangerous?

The interactor reads stdout as protocol messages. Extra text can be interpreted as a malformed query. Use stderr for diagnostics in local testing, and keep protocol output exact.
