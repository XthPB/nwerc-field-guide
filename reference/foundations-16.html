Rerooting, LCA, lifting and tree paths

Rerooting asks: what changes across one edge?

Suppose every vertex contains some demand, total W, and you want the sum of weighted distances from every possible root. Compute one root's answer and each child subtree's demand S. Moving the root across an edge of length c makes S units c closer and W−S units c farther:

answer[child] = answer[parent] + c(W−2S)
answer[v]=answer[u]+edgeLength*(totalWeight-2*subtreeWeight[v]);

One postorder computes subtree information; one preorder propagates outside information. Total time is O(n). Compressing Commands applies this to a trie of directory paths, where repeated files contribute multiplicity to demand.

General rerooting as messages

For every directed edge u→v, imagine a message summarising the component on u's side when that edge is cut. To send u→v, combine incoming messages from all neighbours except v and add u's local contribution. Prefix/suffix aggregates let you exclude each neighbour in O(1) after O(deg(u)) work, even when division is unavailable.

This handles maxima with ties, products modulo a composite number, and non-invertible merges. Do not divide out a child's contribution unless division is mathematically valid and zero-safe.

Binary lifting: powers of a function

Let up[0][v] be v's parent or next state. Define up[k][v]=up[k−1][up[k−1][v]]. This jumps 2^k steps. Break a requested jump count into binary bits to answer in O(log K).

for(int k=1;k<LOG;k++) for(int v=0;v<n;v++)
    up[k][v]=up[k-1][up[k-1][v]];
for(int k=0;k<LOG;k++) if(steps>>k&1) v=up[k][v];

Choose LOG from the maximum number of steps, not blindly from n: functional-graph queries may ask for 10^18 steps. Define a root/sentinel transition so table lookups stay in bounds.

Lowest common ancestor

First lift the deeper vertex to equal depth. If they differ, inspect jump powers from large to small and lift both whenever their ancestors differ. Their common parent is the LCA. Preprocessing costs O(n log n); queries cost O(log n). Weighted distance is distRoot[u]+distRoot[v]-2·distRoot[lca].

Euler-tour entry times turn subtrees into contiguous intervals. This supports subtree sums or updates with Fenwick/segment trees. A full Euler walk plus range minimum over depths gives another LCA method.

Heavy-light decomposition

Choose the largest child subtree as heavy. Every light edge at least halves the remaining subtree size, so a root path crosses O(log n) light edges. Number vertices along heavy chains; a tree path splits into O(log n) array intervals. With O(log n) segment queries, a path operation costs O(log² n).

For noncommutative operations such as matrix products or string concatenation, preserve direction when combining chain pieces. Many simple HLD templates silently assume sum/max, where order does not matter.

Centroid decomposition

Remove a centroid whose remaining components each have at most half the vertices, then recurse. Depth is O(log n). Store distances to centroid ancestors to answer nearest-marked-vertex queries or count paths through a separator. Avoid double counting paths that lie wholly inside one child component.

Checkpoint: is binary lifting only a tree technique?

No. It accelerates repeated application of any deterministic transition. International Irregularities uses monotone travel jumps; functional graphs use successors; automata can use repeated transformations.
