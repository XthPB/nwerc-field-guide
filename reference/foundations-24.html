Combinatorics and counting · Foundations

Counting, combinatorics and generating functions

You have three towns in a line, A–B–C. Count the nonempty sets of towns connected by roads that stay inside the set. The set containing all three can be discovered starting from A, B or C. How can you count that set exactly once on a larger tree?

Count by a unique witness

A counting solution needs both coverage and no double counting. Connected tree subsets have a unique highest vertex. Rectangles can be assigned a chosen corner pair or a canonical minimum bar. If several witnesses are possible, divide only when every object is counted the same number of times; otherwise use a tie-breaking rule.

The multiplication principle combines independent choices. The addition principle combines disjoint cases. Most difficult counting recurrences are careful applications of these two ideas.

Binomial coefficients and modular limits

Pascal's recurrence C(n,k)=C(n−1,k−1)+C(n−1,k) works with any modulus. Factorials and inverse factorials give O(1) queries after O(N) preprocessing modulo a prime p when the factorials being inverted are nonzero, typically N<p. If n≥p, blindly inverting n! fails; Lucas-type or prime-factor methods may be needed.

Stars and bars counts nonnegative solutions to x₁+…+x_k=S as C(S+k−1,k−1). Upper bounds require correction, often by inclusion–exclusion or DP.

Inclusion–exclusion

To count objects avoiding several bad properties, subtract objects with one bad property, add intersections of two, and so on. For each object with t bad properties, its total coefficient is (1−1)^t, which is 1 only when t=0. This is the proof, not merely a sign pattern.

Subset masks make inclusion–exclusion practical when the number of properties is small. Be wary when intersections are not easy to count; 2^k easy terms and 2^k hard subproblems are very different algorithms.

Generating functions are weighted bookkeeping

For choosing any subset of items with weights w_i, the polynomial ∏(1+x^w_i) has coefficient of x^s equal to the number of subsets of weight s. Multiplication performs the same convolution as knapsack DP.

For connected tree subsets, P_u=x∏(1+P_v) encodes the “skip this child or attach a connected child subset” choice. The polynomial is a readable model even when you implement the coefficients with loops.

vector<long long> multiply(const vector<long long>& a,const vector<long long>& b) {
    vector<long long> c(a.size()+b.size()-1);
    for(int i=0;i<(int)a.size();i++) for(int j=0;j<(int)b.size();j++)
        c[i+j]=(c[i+j]+a[i]*b[j])%MOD;
    return c;
}

FFT and NTT

A convolution of lengths n and m can be computed in O((n+m) log(n+m)) using transforms. FFT uses complex roots of unity and needs rounding/error analysis for exact integer answers. NTT works modulo a prime with a suitable root of unity and transform length dividing p−1. Pad to at least n+m−1 to avoid circular wraparound.

One NTT modulus may not represent the desired exact coefficient range or target modulus. Multiple primes plus CRT can reconstruct larger integers when their product exceeds the coefficient bound. AtCoder Library offers a tested convolution implementation; still understand its modulus and length requirements.

Symmetry and Burnside

To count objects up to rotations or reflections, average the number fixed by each group action. Do not simply divide all labelled objects by the group size: symmetric objects have smaller orbits. Burnside's lemma corrects exactly this issue. It is a useful extension beyond the patterns directly observed here.

Checkpoint: why does naive division by n fail when counting necklaces?

A monochromatic necklace has only one distinct rotation, while a generic necklace has n. Orbit sizes differ, so every object is not overcounted by the same factor.
