One condition changes the whole knapsack

Three parties have 4, 3 and 2 seats. A group needs 5 of the 9 seats to win. How many winning groups need every one of their members?

Imagine switches with strengths 4, 4, 3, 2. An alarm sounds when total strength exceeds 6. Begin with existence. A 7 can be made as 4+3. A bitset answers yes. Now count ways. The two 4s belong to different switches, so there are two ways to make 7. Now count minimal alarm sets of any strength. This is the crucial change.

If a chosen set has total T and minimum strength w, removing any chosen switch drops the total to at most 6 exactly when T−w≤6. Removing the smallest leaves the largest remainder. Sort the labeled switches from heavy to light. Charge each subset to the last switch it takes, breaking equal-strength ties by original index. The earlier members have total s, hence 6−w < s ≤ 6. Their identities no longer affect the test.

There are three minimal sets. Query before insertion and keep only earlier sums at most 6. An ascending sum loop would reuse a switch. If the follow-up asks for exactly three switches, add a cardinality axis. If it asks for the highest profit, keep max-profit rather than count in each exact sum. NWERC 2024 D · Jury slide 11

Two coordinates can call for three different tools

Among pairs with first coordinate from 2 through 6, return the ID with smallest second coordinate. Which coordinate should the tree index?

Suppose records have an eligibility value a and a score b. For repeatedly querying the best b among A≤a≤B, sort on a and store (b,id) in a range-minimum structure. If the interval only grows to the right from a fixed start, a running best suffices. If each chosen record must increase both a and b and has a third field profit, sorting and querying the best predecessor becomes weighted chain DP. Batch equal a when strict increase is required. Consider now two shelves of heights 3 and 8, each holding two books when wide or one when narrow. Books have heights 3,7,8. Narrowing the short shelf leaves a feasible assignment. Narrowing the tall one does not. In general, move lost capacity from a taller shelf to a shorter shelf: any book displaced on the short shelf still fits the newly freed tall slot. With the number of narrow shelves fixed, take the shortest shelves. Check taller books against taller shelves in sorted order. Repeated shifts inside a tree problem

There are five identical items of weight 3. Can you compress the stock while preserving every attainable total?

A tree splits into branches of sizes 1,1,1,1,2,3 at a candidate centre. An orientation argument can leave only the choice of which branches are on one side. Maximizing s(S−s) asks for an achievable sum closest to S/2. Here S=9, and a sum of 4 or 5 achieves 20. The graph has disappeared from this subproblem.

Many leaves create many identical shifts. With at least three 1s, keeping a 1 and exchanging two others for a 2 preserves all feasible totals. Repeating the exchange by increasing weight leaves at most two copies per weight. If d distinct positive weights remain, their sum is at least d(d+1)/2, so d is O(√S). You now perform O(√S) packed bitset shifts instead of one per branch. The exchange preserves feasibility, so it would be wrong for a follow-up asking how many orientations give the optimum. SWERC 2021–22, Gastronomic Event, p. 21

A knapsack that changes over time · CF 601E, 2800

A sequence branches into two versions. Updating one branch must leave the old prefix available to its sibling. How can both see the correct scores?

A static maximum-value knapsack costs O(W) per new item. Deletion is asymmetric. At capacity 2, item B might have displaced item A from every maximum where A mattered. Subtracting B’s value gives no way to recover A. The useful observation is that every item has a contiguous lifetime in the known event sequence.

Build a segment tree over event times. Assign an item active on [l,r) to the O(log Q) disjoint tree nodes that exactly cover its lifetime. At a node inherit the parent’s capacity row and insert that node’s items in descending-capacity order. At a leaf, there is exactly one copy of each active item along its root path. Visit the sibling starting from the original parent row. For capacity W the bounds are O(IW log Q + QW) time with a full copy at every visited node, O(W log Q) live row storage plus the interval lists. The official output also combines the whole capacity row into a specified hash.

At cap 2 let A=(weight 2,value 5) live on [0,3), and B=(2,8) on [1,2). At times 0,1,2 the optimum is 5,8,5. The restored value comes from returning to a parent snapshot. This reasoning applies equally to feasibility and min-cost tables. A count table with a positive-weight one-use item has an additional option, polynomial division by 1+zʷ. Starting at both ends unlocks a string DP · CF 932G, 2900

You want the fewest palindrome blocks that spell ababa. Which cuts can create its last block?

The first and last block must be identical in forward order. Their lengths need not be known. Read the original string by alternating its leftmost and rightmost unused characters. An outer pair of equal blocks of length k becomes one even palindrome of length 2k. To see the equivalence, write the alternating segment as L₁,Rₖ,L₂,Rₖ₋₁,…,Lₖ,R₁. Its first and last characters agree exactly if L₁=R₁. The next pair does the same for Lₖ and Rₖ. Continuing checks every character.

For abccab, the interleaving is abbacc. The factorization abba | cc corresponds to ab | c | c | ab. Each valid paired partition gives one sequence of even palindromes and conversely. Set ways[0]=1. At even prefix i, add ways[i−ℓ] for every palindromic suffix length ℓ; keep ways at odd indices zero. A quadratic enumeration fails when a prefix has linearly many palindromic suffixes.

An eertree stores all distinct palindromes. A suffix link goes to the longest proper palindromic suffix. For a node v set diff[v]=len[v]−len[link[v]]. A series link skips the whole run of equal differences. At position i, the shortest length in the run headed by v is len[series[v]]+diff[v]. Seed its contribution from that one cut. When diff[v]=diff[link[v]], the cached sum for link[v] from the aligned earlier position accounts for the rest of this arithmetic progression. The cache must be updated even on odd positions, although odd positions do not accept completed factorizations. There are O(log n) series per prefix. The compilable C++ routine appears with the palindrome lesson. CF 932G · Rubinchik and Shur, eertree and series links · Implementation

Powering a dense-looking transition · CF 453D, 3000

Combine two distributions when a pair's resulting label is the bitwise XOR of its labels. How many ways produce zero?

If states are b-bit words and the step weight from v to u depends only on popcount(u XOR v), every matrix row is a relabeled copy of one kernel. Define K[z]=weight[popcount(z)]. One step is F′[u]=ΣᵥF[v]K[u XOR v]. The key observation is translation invariance under XOR. Repeating a dense matrix multiplication would throw it away.

The Walsh–Hadamard transform H changes XOR convolution to pointwise multiplication. After t steps, transform F and K, multiply H(F)[j] by H(K)[j]ᵗ at every j, and transform again. Since H²=NI with N=2ᵇ, the second transform yields N times the wanted vector. The modulus can be even. Compute everything modulo Np, take each final residue in [0,Np), then divide that ordinary integer by N. Congruence modulo Np makes the answer correct modulo p, and divisibility is guaranteed by H². Widen products before taking remainders.

For N=2, F=[1,2], K=[1,3], two direct steps give [7,5] then [22,26]. Modulo 6 the result is [4,2]. The lifted transform works modulo 12: H(F)=[3,11], H(K)=[4,10], and after pointwise powering/multiplication the transformed result is [0,8]. Transform again to [8,4] and divide by 2. Time is O(N(log N+log t)), memory O(N). CF 453D · Implementation

A number-theory cost turns into range updates · CF 1603D, 3000

Split a string into segments and earn the number of different letters in each segment. How do candidate cuts change when you append a letter?

A partition DP is immediate. The difficult part is evaluating all candidate last segments fast enough. The cost of [l,r] counts pairs l≤i≤j≤r with gcd(i,j)≥l. Fix the new right endpoint r. For each divisor d of r, there are φ(r/d) values of i from 1 to r with gcd(i,r)=d. This includes i=r because φ(1)=1. Every such pair is valid for exactly the starts l≤d: the condition i≥l now follows from i≥d. For a previous cut j=l−1, add φ(r/d) to every cut j∈[0,d−1].

At fixed group count g, initialize a lazy minimum tree with the previous row at each cut. Sweep r upward, applying those prefix additions, then query the cheapest cut g−1…r−1. After endpoint r, every candidate j<r has accumulated precisely its last-segment cost. Future cuts j≥r have received no increments. This proves the recurrence without an argmin-monotonicity assumption.

A second observation bounds the layers. In each interval [2ᵃ,2ᵃ⁺¹−1], no two distinct members can both be multiples of d≥2ᵃ. Only diagonal pairs contribute. Thus floor(log₂ n)+1 groups suffice to reach the absolute lower bound n; extra cuts can preserve it. Precompute smaller layers for all queried n up to N. There are Σᵣτ(r)=O(N log N) divisor updates per layer. With a segment tree this derivation costs O(GN log² N) time and O(N log N+GN) space with stored divisor lists and all answer rows, G≤1+floor(log₂ N). Constants matter at the published limit. This is an independently derived route; the numerical checks cover small inputs.

For n=4, r=4 has d=1,2,4 with multiplicities 2,1,1. The new pair contributions for starts l=1,2,3,4 are 4,2,1,1. With two groups, [1] | [2,4] costs 1+4=5, and [1,2] | [3,4] costs 3+2=5. With three groups [1]|[2,3]|[4], the lower bound 4 is attained. CF 1603D · Range-update lesson

Three strings make a 3D table · CF 1149B, 2200

Can you weave aa, b and c into the host abac as a subsequence?

Consider three small strings aa, b, c and a host abac. Are there disjoint positions for the three strings, preserving the order within each one? You decide the order between strings. For example, reading all of aa first finishes at host position 3, too late for b. Interleaving them as a,b,a,c works.

Start from a table indexed by the three consumed lengths and the position reached in the host. Now fix just the first three coordinates. A history finishing at 2 has every continuation available to a history finishing at 3 because it can skip position 3. This proves that the positional axis can become a single minimum inside a cell. Earliest finishing time is the exact statistic needed for future feasibility.

At state (2,1,0), the last symbol can be the second a or the b. In the first case state (1,1,0) ends at 2 and the next a is at 3. In the second case (2,0,0) already ends at 3 and there is no later b. The same distinction applies to optimization over schedules. When an earlier completion makes every future choice easier, store the earliest finish as the payload. The two states of a tree vertex with a degree limit

Find the most edges of a tree you can mark if no vertex may touch two marked edges.

Choose weighted edges in a tree. Vertex u permits at most bᵤ selected incident edges. Imagine cutting the edge from u to its parent. Only one fact crosses that cut: whether the parent took the edge and used one of u’s slots. Write Fᵤ(0) and Fᵤ(1) for the best strictly-below-u reward with that many slots already consumed. Set the value to negative infinity when this reservation exceeds bᵤ.

Each child v initially contributes Fᵥ(0) if its edge is omitted. Taking uv changes that contribution to wᵤᵥ+Fᵥ(1). Subtract the baseline to get one independent gain per child. Choose the largest positive gains, up to bᵤ minus the parent reservation. If the input requires an exact degree, an optimum may be forced to include negative gains, and feasibility must be checked separately.

A centre u has capacity 2 and three children. The edges to two leaves pay 9 and 4. The third edge pays 7, but that child has only one slot and can instead take an edge worth 6 below it. The baseline is 6. The three gains are 9, 4 and 1. With its parent edge absent, u earns 6+9+4=19. With its parent edge already chosen, u earns 6+9=15 below itself. Choosing the locally largest two edge weights 9 and 7 would earn only 16.

Sorting once per vertex suffices for both states, in O(Σᵤ deg(u) log(deg(u)+1)) time. For quota one only the best gain is needed. If selecting one child changes how profitable a different child becomes, their gains cease to be independent and a child-by-child merge is the next model. When the data structure must store an entire DP

Letters of a string change online. How can you recompute the cheapest edits satisfying a small automaton after each change?

You receive many substring queries. For a small example, delete as few characters as possible so the kept text has no adjacent a characters. There are two states. State 0 means the preceding kept character is absent or different from a. State 1 means it is a. A middle block does not know which state precedes it. A single minimum deletion count for the block loses this dependence.

For the block a, with rows for entry states 0,1 and columns for exit states 0,1, the two rows of its matrix are [1,0] and [∞,1]. For instance, entering in state 1 makes keeping this a illegal. Deleting it leaves the old last-kept character in place. For b, keeping the character always enters state 0. Its two rows are [0,∞] and [0,1]. The lower-right 1 means deleting b preserves the earlier a.

Txy(p,q)=min⁡r{Tx(p,r)+Ty(r,q)}T_{xy}(p,q)=\min_r\{T_x(p,r)+T_y(r,q)\}Txy​(p,q)=rmin​{Tx​(p,r)+Ty​(r,q)}

Across aa the product has rows [2,1] and [∞,2]. Starting fresh, take the minimum of row 0, which is 1. Inserting a b between the two a characters changes the answer to 0. A segment tree computes the appropriate ordered product per range, and a point edit replaces a single leaf. Left-to-right order matters. For instance, starting in state 0 the cheapest way to finish in state 1 costs 1 on ab (delete b) and 0 on ba (keep both).

The Codeforces variant has a different automaton for required and forbidden subsequences. The reusable idea is to make the value of a segment independent of its neighbours by storing its action on every incoming state. Animate the product · CF 750E

Why the outer search shrinks. Bundle two 1s into a 2, two 5s into a 10, and similarly 10→20, 50→100 and 100→200 using pairs. Five 2s can become a 10, and five 20s can become a 100. Any selected bundle expands to its constituents with the same value. If the original payout missed half, so does the new one. Each exchange reduces the note count, so repeating exchanges reaches a payout inside the smaller search family. A total can still have several such payouts.

How to finish. For 1,5,10,50,100 try counts 0 or 1. For 2 and 20 try 0 through 4. Try each affordable number of 500s. The residual must be a nonnegative multiple of 200, which fixes the final count. Run the bitset on each admitted payout. Return the first missing-half witness. If none exists, every payout splits. For odd n, n notes of value 1 already give a witness.

At n=4 every payout reduces to two 2s and bit 2 is set. At n=12, [10,2] is a counterexample. Compare this with repeated-weight carrying, which keeps a spare copy because it needs to preserve all reachable sums. Here it is enough to preserve a missing sum.
