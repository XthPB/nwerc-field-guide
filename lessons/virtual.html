Sparse marked vertices and virtual-tree DP

A huge fixed tree receives queries mentioning only a few marked vertices. How can you price a connecting subtree per query?

Work through the choice

Keep the marked vertices and the places their paths meet. Sort marks by traversal order, add the necessary lowest common ancestors, and replace chains of unmarked vertices by single edges with their original distances.

The rule you can reuse

If a query marks k vertices in a large fixed tree, retain marked vertices and the LCAs at which their paths meet. A chain of omitted vertices becomes one virtual edge. Precompute the quantity the compressed chain contributes.

∣Vvirtual∣≤2k−1(k≥1)\lvert V_{\rm virtual}\rvert\le 2k-1\qquad(k\ge1)∣Vvirtual​∣≤2k−1(k≥1)

Sort by Euler-entry time, add LCAs of consecutive vertices, sort/deduplicate again, then use an ancestor stack to attach each vertex to its nearest retained ancestor.

Check the boundary. For separator tasks remember whether a virtual edge represents a single original edge. Adjacent marked vertices can behave differently from vertices separated by an unmarked removable node.

Cost At most 2k−1 virtual vertices for k≥1 before adding an optional fixed root. O(k log k+k·LCAquery) per query after preprocessing.

From idea to code

  • Lowest common ancestors
    Use the common ancestor to compute tree distances or compress marked paths. A virtual tree also needs traversal order and ancestor tests.
  • Rooted tree DP and rerooting
    Use reverse traversal for bottom-up child messages. Use forward traversal for the parent contribution. Derive a new message when the objective differs from distance or subtree size.
