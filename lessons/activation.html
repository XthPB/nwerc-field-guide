A predecessor must become eligible before a range maximum can see it

Choose weighted positions on a line whose pairwise spacing is large enough for both endpoints. When does an old position become usable?

Work through the choice

The old position's own spacing requirement decides the earliest time it becomes eligible. Schedule its DP score to enter a range structure at that time. The current position's requirement then gives a separate bound for the query.

The rule you can reuse

Two ordered choices j<i require i−j>max(aᵢ,aⱼ). Consecutive chosen pairs suffice: for any farther-apart pair, the gap exceeds the gap to each endpoint’s nearest chosen neighbour. Split the predecessor condition into a release time for j and an upper-bound query for i.

i−j>max⁡(ai,aj)  ⟺  i≥j+aj+1 ∧ j≤i−ai−1i-j>\max(a_i,a_j)\iff i\ge j+a_j+1\ \land\ j\le i-a_i-1i−j>max(ai​,aj​)⟺i≥j+aj​+1 ∧ j≤i−ai​−1

Release D[j] at time j+aⱼ+1 into a prefix-maximum tree indexed by j. At i, first process releases, then query j≤i−aᵢ−1. Set D[i]=aᵢ+max(0,query). Schedule its future release with a wide integer.

Check the boundary. Testing just i−j>aᵢ ignores the previous endpoint’s requirement. Release events enforce that condition independently. A large aⱼ can put the release past n, where it can be dropped.

Cost O(n log n) with time buckets or a priority queue plus a Fenwick prefix maximum. CF 2244G, rated 1900.

From idea to code

  • Bottom-up segment tree
    The original combine is addition over a half-open interval. For a min, max, witness or matrix payload, update the stored type, combine and empty identity together. Preserve combination order for matrices.
  • Coordinate compression
    Compression preserves order and equality. Convert open and closed query bounds with lower_bound and upper_bound. Original distances must still use the uncompressed coordinates.
