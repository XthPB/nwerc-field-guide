Restrict the previous choices · Lesson 154 of 235

Accumulate range rewards between the few times a state can change

You gain skill points occasionally but face many checks between gains. How can you score all allocations without touching every state per check?

1. Work one example

With a fixed total of points, assigning i to one skill determines the other. Each check succeeds on a prefix or suffix of i values. Accumulate these rewards with a difference array until the next gain, then make the choice for the new point.

2. What do we need to remember?

Between two actual decisions the allocation cannot change. Add up all intervening tests as range rewards, then process the next decision once.

3. How do we get the next answer?

When millions of checks are interspersed with only m decisions, keep one DP layer per decision. Between two decisions the allocation stays fixed, so all intervening checks are range additions to candidate states. One prefix pass applies them together.

I+S=t,Dt+1(i)=max⁡(Dt(i),Dt(i−1))after the checksI+S=t,\qquad D_{t+1}(i)=\max(D_t(i),D_t(i-1))\quad\text{after the checks}I+S=t,Dt+1​(i)=max(Dt​(i),Dt​(i−1))after the checks

After t points, let i be intelligence and t−i strength. An intelligence check q awards +1 on i≥q. A strength check q awards +1 on i≤t−q. At the next point apply pending additions, then new[i]=max(old[i],old[i−1]) with valid predecessors.

Check the boundary. Begin with only state i=0 reachable. Tests before the first point and after the last one are real. Clamp every interval to 0…t and flush the final difference array. Range additions alone cannot move a point between attributes.

Cost O(n+m²) time and O(m) memory, since t+1 states are materialized only at the m allocation events. The same idea applies whenever transition times are sparse compared with scoring events.

Try one change

Nothing about a player's allocation can change during ten tests. Must you run ten separate state-choice transitions?

See the reasoning

No. Compute the total reward those ten tests give each fixed allocation, then run the choice transition when a new allocation decision becomes available.
