‹ Dynamic programming on trees

Merge a child’s size or budget distribution

How many connected vertex sets of each size include the root?

Work through the choice

For each child, skip its subtree or include a connected set touching that child. The root connects independently chosen pieces. Merge the length distributions with a double loop as in knapsack.

The rule you can reuse

A child can contribute t selected vertices, cost units or endpoints. Its whole table is convolved with the partial table for processed children. Enforce the interface first, then distribute the budget.

Fu(z)=z∏v∈child(u)(1+Fv(z))F_u(z)=z\prod_{v\in\mathrm{child}(u)}(1+F_v(z))Fu​(z)=zv∈child(u)∏​(1+Fv​(z))

For connected sets containing u start A[1]=1. For each child v replace A by A × (1+Fᵥ(z)), as a polynomial by size. Sum Fᵤ[k] over u for all connected sets of size k.

Check the boundary. Use a fresh vector for each child or a proved update order. Enumerating every child convolution as K² is a safe upper bound; claiming an improved bound needs subtree-size accounting.

Cost O(nK²) safe for truncated naive convolutions. For full untruncated size counts, bounding by actual subtree sizes gives O(n²) total on a tree.

From idea to code

  • Rooted tree DP and rerooting
    Use reverse traversal for bottom-up child messages. Use forward traversal for the parent contribution. Derive a new message when the objective differs from distance or subtree size.
  • 0/1 knapsack
    Use the descending capacity loop for one-use items. The initial zeros in this implementation mean “at most this capacity.” For exact weight, mark initially unreachable cells before the first update.
