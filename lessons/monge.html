Recognize a cost matrix · Lesson 166 of 235

Why the best partition cut moves to the right

Partition a nonnegative array into groups, paying the square of each group's sum. How can you avoid trying every cut at every endpoint?

1. Work one example

First prove the best cut can only move right as the endpoint moves right, using a four-cost inequality. Solve the middle endpoint. Its best cut becomes a boundary for both remaining halves, reducing the number of candidates examined.

2. What do we need to remember?

Before narrowing the search, prove that the best cut cannot move backward as the endpoint advances.

3. How do we get the next answer?

Write the slow, correct recurrence first. If a consistent minimizing split opt[i] never moves left as i increases, calculating the midpoint restricts the candidate intervals for both halves. A Monge cost with ordered feasible splits is a common sufficient condition.

C(a,c)+C(b,d)≤C(a,d)+C(b,c)(a≤b≤c≤d)C(a,c)+C(b,d)\le C(a,d)+C(b,c)\qquad(a\le b\le c\le d)C(a,c)+C(b,d)≤C(a,d)+C(b,c)(a≤b≤c≤d)

D[g,i]=minⱼ(prev[j]+C(j,i)). For a≤b≤c≤d prove C(a,c)+C(b,d)≤C(a,d)+C(b,c), or prove monotone opt directly. Use a consistent tie rule.

Check the boundary. Solve only j<i and j≥g−1. Monotonicity of DP values alone says nothing about the minimizing indices. Signed increments can break this proof.

Cost O(Kn log n) cost evaluations; O(n) rolling rows. If computing C costs T rather than O(1), explicitly account for T or use a movable cost oracle.

Try one change

On one DP layer the best cut at position 10 is 4. When may you promise that the best cut at position 11 is at least 4?

See the reasoning

Only after proving monotonicity with a consistent tie rule, often via the Monge inequality. Merely observing a few increasing best cuts is insufficient.

From idea to code

  • Divide-and-conquer partition DP
    Use the recursion once optimal cuts are proven monotone. For exactly k nonempty groups, compute only i ≥ k and permit j ≥ k−1. Use the reachable prefix range on each layer.
Worked C++17 implementation
// Exactly k nonempty pieces, cost squared segment sum. Inputs >= 0.
// Contract: 1 <= k <= n and square of total sum < INF.
inline i64 square_partition(const std::vector<int>& a, int k) {
    const i64 inf = std::numeric_limits<i64>::max()/4;
    int n = static_cast<int>(a.size());
    std::vector<i64> pref(n+1), prev(n+1, inf), next(n+1);
    for (int i = 0; i < n; ++i) pref[i+1] = pref[i] + a[i];
    prev[0] = 0;
    for (int g = 1; g <= k; ++g) {
        std::fill(next.begin(), next.end(), inf);
        auto fill = [&](auto&& self, int l, int r, int lo, int hi) -> void {
            if (l > r) return;
            int mid = l + (r-l)/2, best = lo;
            for (int j = lo; j <= std::min(hi, mid-1); ++j) {
                if (prev[j] == inf) continue;
                i64 width = pref[mid] - pref[j];
                i64 candidate = prev[j] + width*width;
                if (candidate < next[mid]) {
                    next[mid] = candidate;
                    best = j;
                }
            }
            self(self, l, mid-1, lo, best);
            self(self, mid+1, r, best, hi);
        };
        fill(fill, g, n, g-1, n-1);
        prev.swap(next);
    }
    return prev[n];
}
