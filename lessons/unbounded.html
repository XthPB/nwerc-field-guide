Reuse, bounded stock, or one choice per group

You have a budget and a shop lists the cost and benefit of each upgrade. Find the largest total benefit you can afford. In the worked shop two alternatives belong to the same group, so you may buy at most one of them. Other shops allow repeated purchases or give a stock limit.

1. Work one example

Each option must start from the table before entering the shop. If the second option reads values already produced by the first, it buys two upgrades. Unlimited items deliberately read today's values to allow reuse.

2. What do we need to remember?

Ask how good an exact total can be after appending one reusable item. The smaller total may already use that same item.

3. How do we get the next answer?

An unlimited positive-weight item can read the current layer at a smaller sum. A group with mutually exclusive options must read the entire previous group. A stock bound sits between these cases.

D(s)←max⁡{D(s),D(s−w)+v}(s=w,w+1,…,W)D(s)\gets\max\{D(s),D(s-w)+v\}\qquad(s=w,w+1,\ldots,W)D(s)←max{D(s),D(s−w)+v}(s=w,w+1,…,W)

Unlimited max: d[s]=max(d[s],d[s−w]+v), ascending. Group: new[s]=max over options o of old[s−wₒ]+vₒ; include a zero option if skipping is allowed.

Check the boundary. For bounded optimization or existence, subdivide c copies into 1,2,4,… and a final remainder. For c=6 the bundles 1,2,3 represent 3 twice, so this transformation can overcount.

Cost Grouped O(W × total options). Binary bundles O(W Σ log(c+1)). An unlimited zero-weight positive-profit item makes the optimum unbounded.

Try one change

A 3-value coin type has unlimited supply. When may you use the total 3 just made to reach 6?

See the reasoning

Immediately. The new 3 already represents a valid purchase using this type. An ascending sum loop deliberately permits its reuse.

From idea to code

  • Minimum coins for an exact amount with unlimited stock
    Use positive integer denominations and a target small enough for a table. The return value is −1 when the exact target is unreachable. A divisibility chain also admits greedy exchanges even for huge targets.
  • 0/1 knapsack
    Use the descending capacity loop for one-use items. The initial zeros in this implementation mean “at most this capacity.” For exact weight, mark initially unreachable cells before the first update.

    A payment may use unlimited copies of given coin denominations. Find the fewest coins that make exactly the target sum, or decide it cannot be made.

    Track the fewest coins for each exact sum. Every denomination can be used repeatedly. Skip unreachable predecessors before adding one.

    Cut a ribbon into pieces using only three allowed lengths. All the ribbon must be used. What is the greatest possible number of pieces?

    Compute the greatest number of pieces for each exact total in increasing order. Adapt the unlimited-coin template by maximizing its candidate instead of minimizing it. Keep −1 for unreachable totals and never extend those states.

  • CF 996A · Hit the Lottery 800

    Given banknotes worth 1, 5, 10, 20 and 100 and an exact withdrawal amount, find the minimum number of notes needed.

    The bill sizes 1, 5, 10, 20 and 100 form a divisibility chain. Exchange a full group of smaller notes for one larger note, then use division and remainder from largest to smallest. For arbitrary denominations the same minimum-coin question needs an exact-sum DP. With 1, 3 and 4, greedily paying 6 takes three coins while 3 + 3 takes two.
