Pair paths through one separator exactly once

Count unordered pairs of tree vertices at distance K. How do you prevent counting the same pair at several separators?

Work through the choice

At a centroid, join one child branch only with previously processed branches. Their paths necessarily pass through the centroid. Then recurse within each branch to handle pairs whose paths avoid it.

The rule you can reuse

For all pairs of vertices satisfying a path-length or path-label condition, separate by a centroid and charge a pair to the first removed vertex on its path. Distances then combine by addition, or labels by another associative rule.

Nnew=∑d in new branchfreq(K−d)N_{\rm new}=\sum_{d\ \mathrm{in\ new\ branch}}\mathrm{freq}(K-d)Nnew​=d in new branch∑​freq(K−d)

At each centroid initialize freq[0]=1. For each child component, query freq[K−d] for every distance d in it, then insert that whole component’s distances. Recurse after removing the centroid.

Check the boundary. Correct or exclude pairs with endpoints in the same child. Pruning d>K needs nonnegative distances. Reset only touched counts to preserve the intended complexity.

Cost O(n log n) distance visits for balanced decomposition, times dictionary operation cost. For small fixed K, tree DP merging depth-count arrays can be simpler.

From idea to code

  • Centroid decomposition
    For path counts, query earlier child branches before inserting distances from the current branch. Recurse after removing the centroid so that other paths are attributed exactly once.
  • Rooted tree DP and rerooting
    Use reverse traversal for bottom-up child messages. Use forward traversal for the parent contribution. Derive a new message when the objective differs from distance or subtree size.
