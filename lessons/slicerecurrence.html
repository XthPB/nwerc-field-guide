Build a long DP row by reusing slices

One update copies two long pieces of yesterday's DP array in a new order. How can you process many days without physically copying every cell?

1. Work one example

Describe the new row as two index ranges of the old row. An immutable sequence tree can split and join ranges while sharing unchanged subtrees. Keep balance and handle repeated references so indexing remains efficient.

2. What do we need to remember?

A starting balance either increases or decreases by today’s cost. Each region reads a shifted slice of the next day’s row.

3. How do we get the next answer?

A day with cost a maps starting balance b to b+a for b<a and to b−a otherwise. To answer every suffix from b=0, let Fᵢ(b) be the final balance starting day i at b. With 1≤a≤n the domain 0…2n−1 is closed. F after the last day is the identity sequence.

Fi=V[a:2a] ∥ V[0:L−a],V=Fi+1,L=2nF_i=V[a:2a]\ \Vert\ V[0:L-a],\qquad V=F_{i+1},\quad L=2nFi​=V[a:2a] ∥ V[0:L−a],V=Fi+1​,L=2n

Write V=Fᵢ₊₁ as a zero-indexed sequence of length L=2n. The next row is concatenate(V[a:2a],V[0:L−a]), using half-open slices. Each output is the first value of this row. A persistent balanced sequence tree performs slices and concatenation while sharing intact subtrees.

Check the boundary. The source intervals can overlap. Slices must share immutable nodes or be copied without mutating their common ancestor. An immutable AVL rope with size, balanced join and split gives logarithmic operations even when children contain repeated shared pieces. Destructive splitting or relying on distinct treap priorities after duplication needs a separate proof.

Cost O(n log n) with deterministic logarithmic split/join and index access. An initial identity row costs O(n) with balanced construction. O(n log n) allocated nodes suffice across all days. CF 2242F, rated 2800.

Try one change

If a new row is a concatenation of slices from the old row, may writing its first slice overwrite data still needed for the second?

See the reasoning

No. Think of the old row as immutable while building the new one. Representing slices by sequence pieces can avoid copying their elements.
