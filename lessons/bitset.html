‹ Knapsack and subset sum

Update many reachable sums with one shift

Which totals can you make with weights 2, 3 and 3, using each once?

Work through the choice

Write a row of yes/no switches, one per sum. Shifting a copy rightward along the number line by 3 shows what changes when that item is taken. Keep the old lit switches too. A machine word updates many switches together.

The rule you can reuse

Use this when the only information needed per sum is yes/no. A shift by w moves all previous witnesses to their shifted sums together. OR lets each witness skip or take the new item.

B←BOR(B≪w),B0=1B\gets B\mathbin{\mathrm{OR}}(B\ll w),\qquad B_0=1B←BOR(B≪w),B0​=1

B starts with bit 0. For each w, B ← B OR (B ≪ w), truncated to bits 0…W.

Check the boundary. OR destroys multiplicity. XOR gives parity, which is different again. For a hand-rolled word shift, avoid shifting by the word width, keep the old row intact or traverse high to low, and mask the final word.

Cost O(n⌈(W+1)/w⌉) word operations and O(⌈(W+1)/w⌉) words for w-bit machine words.

From idea to code

  • Bitset subset sum
    Set only bit zero at the start. A shifted copy represents taking one item. OR retains the outcomes of skipping it. Choose MAXS large enough for the actual largest queried sum.
Worked C++17 implementation
// One-use nonnegative weights. W is the largest sum the caller wants.
template <std::size_t W>
std::bitset<W+1> reachable(const std::vector<int>& weights) {
    std::bitset<W+1> bits;
    bits.set(0);
    for (int weight : weights) {
        bits |= bits << weight;
    }
    return bits;
}
