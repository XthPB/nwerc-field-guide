‹ Strings and alignment

Track more than the last character · Lesson 139 of 235

A witness from two thin rows

Given axb and ayb, return an actual longest sequence of letters appearing in order in both strings. You can skip letters freely, but your memory budget holds only a few rows of the usual table. Knowing the optimum length alone will not identify the letters to print.

1. Work one example

Cut the first string after a. For every cut of the other string compute the best left and right lengths using a forward pass and a backward pass. A cut maximizing their sum belongs to an optimal alignment.

2. What do we need to remember?

Forward and backward rows reveal where an optimal alignment crosses the middle. Recurse there to recover a witness with little memory.

3. How do we get the next answer?

To recover an LCS in linear auxiliary space, cut string A in half. Any optimal alignment crosses that horizontal boundary at some split in B. Compute prefix and suffix length rows to find one such split, then recurse.

j∗=arg⁡max⁡j{LCS⁡(AL,B<j)+LCS⁡(AR,B≥j)}j^*=\arg\max_j\{\operatorname{LCS}(A_L,B_{<j})+\operatorname{LCS}(A_R,B_{\ge j})\}j∗=argjmax​{LCS(AL​,B<j​)+LCS(AR​,B≥j​)}

Choose j maximizing LCS(Aleft,B[:j]) + LCS(Aright,B[j:]). Recurse on the two rectangles.

Check the boundary. Suffix rows must be aligned back to the original j coordinates. Release both rows before recursing, pass index ranges, and handle a one-character side directly.

Cost O(nm) time from geometrically decreasing total rectangle area, O(min(n,m)) row space plus recursion/output.

Try one change

You split the first string in half. Which column should the reconstructed alignment cross?

See the reasoning

For every column add the optimal left score and the optimal right score there. Some optimal alignment crosses a maximizing column. Recurse on its two sides.
