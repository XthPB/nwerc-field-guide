Estimate the actual array before choosing a technique

There are 20 cities. Can you store a 64-bit cost for every combination of visited cities and last city?

1. Work one example

Count bytes before writing the recurrence. There are 1,048,576 masks and 20 endpoint slots per mask. The table alone uses 160 MiB. Parent pointers, adjacency and temporary buffers still need space.

2. What do we need to remember?

Count the cells you would allocate and the predecessors each would inspect. Input limits constrain their product.

3. How do we get the next answer?

Compare input length, total positive weight, sum of values, width, number of special objects, alphabet, and distinct reachable states. Multiply dimensions and transitions. Smallest axis and memory layout often determine the algorithm.

bytes=(∏j=1dnj)bytes per cell\text{bytes}=\left(\prod_{j=1}^{d} n_j\right)\text{bytes per cell}bytes=(j=1∏d​nj​)bytes per cell

Bytes = product of dimension lengths × bytes per cell. Count total work across all test cases.

Check the boundary. A phrase like “n≤20” cannot justify enumerating every submask of every mask. At n=20 that is 3²⁰≈3.49 billion pairs.

Cost Separate word operations from scalar operations. Input limits, constants, memory cap and language determine practical cutoffs.

It needs about 381 MiB before any overhead. Look for rolling rows, unreachable states or a different axis before implementing it.

From idea to code

  • Held–Karp path or closed tour
    Set the start city to zero. The two switches in the calling convention are the distance matrix and whether the last edge must return to the depot. For a fixed finishing city read that one endpoint.
  • Meet in the middle for sums
    Keep both lists including the empty subset. For an exact match use equal_range so repeated sums retain their multiplicity. For a closest partner inspect both neighbours of lower_bound.
