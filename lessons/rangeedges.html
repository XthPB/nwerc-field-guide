Replace a fan of interval transitions with segment-tree nodes

One offer lets you pay 4 to travel to any vertex in an entire interval. How do you build a shortest-path graph with many such offers?

1. Work one example

Represent an interval by logarithmically many segment-tree nodes. Direct zero-cost edges towards leaves for an interval of destinations, and upwards for an interval of possible starts. Pay the offer price only once.

2. What do we need to remember?

If one graph transition reaches an entire interval, use a range tree to represent those destinations with shared nodes.

3. How do we get the next answer?

A transition v→each index in [l,r] would produce many identical-weight edges. Use an auxiliary downward tree of zero-cost edges to reach an interval’s leaves through its canonical nodes. Build a separate upward tree for the reverse direction.

[l,r]=I1⊔⋯⊔Im,m=O(log⁡n)[l,r]=I_1\sqcup\cdots\sqcup I_m,\qquad m=O(\log n)[l,r]=I1​⊔⋯⊔Im​,m=O(logn)

For v→range, add weighted edges v→cover nodes in the downward tree. For range→v, use upward edges from leaves to cover nodes, then weighted edges from those nodes to v. Only original leaves connect the two systems.

Check the boundary. Using one bidirectional zero-cost tree would allow travel from any leaf to any other for free. Acyclic expanded transitions permit topological DP. With arbitrary directions and nonnegative costs use Dijkstra.

Cost O(n+q log n) vertices plus edges as a combined size bound, with O(n) actual vertices. Dijkstra costs O((n+q log n)log n) with a heap after construction.

From idea to code

  • Bottom-up segment tree
    The original combine is addition over a half-open interval. For a min, max, witness or matrix payload, update the stored type, combine and empty identity together. Preserve combination order for matrices.
  • Dijkstra on an expanded graph
    First define what constitutes a vertex of the state graph. Construct an edge for each legal transition. All weights used by Dijkstra must be nonnegative.
