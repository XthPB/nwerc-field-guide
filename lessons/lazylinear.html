A range update can act linearly on each stored DP value

Each array entry stores a Fibonacci index. A query adds two to every index in a range. Can you update their Fibonacci sum at once?

1. Work one example

Store neighbouring Fibonacci values together. A fixed matrix advances any such pair by one index. The same matrix applied to the sum of the pairs advances every entry because matrix multiplication distributes over addition.

2. What do we need to remember?

Describe a deferred update by how it transforms every old value. Compose two such transformations in time order.

3. How do we get the next answer?

Suppose each leaf stores a recurrence vector dependent on its local index a. If raising a by x applies the same linear map Mˣ to every vector, a segment can store their sum. Linearity lets the lazy update transform that one sum.

For Fibonacci numbers use v(a)=(Fₐ₊₁,Fₐ) as a column and M=[[1,1],[1,0]]. Over a node store S=Σv(aᵢ). Add x to all its indices by S←MˣS and compose the lazy tag in temporal order.

Check the boundary. An arbitrary nonlinear update does not commute with summation. If a request changes a transition operator at a position rather than the recurrence index of each independent leaf, use an ordered product of operators.

Cost With fixed-size matrices, precompute Mˣ per update in O(log x), then apply it in O(log n) segment visits. Storage is O(n). Caching powers cheaply supports repeated exponents.

    The sheet multiplies with ordinary modular addition and multiplication. For minimum-cost transitions replace those by min and plus, use an infinite unreachable value, and skip unreachable additions.
