Recognize a cost matrix · Lesson 167 of 235

Bound the split between two shorter intervals

You have nonnegative pile weights in a row. A move merges two neighboring piles and costs their combined weight. Find the minimum total cost to merge the whole row. Many overlapping intervals need almost the same search for their final merge.

1. Work one example

The optimal split of an interval is sandwiched between suitably tie-broken optimal splits of its two neighbours of length one less. Once the cost inequalities hold, these neighbours give a short search band across each diagonal.

2. What do we need to remember?

For interval DP the best split can sometimes be trapped between the best splits of two neighboring intervals. Verify the required cost inequalities first.

3. How do we get the next answer?

When interval merge cost C(l,r) is independent of the final split, two neighbouring shorter intervals may bound the best split. Check the quadrangle inequality and nested-interval monotonicity of C.

opt⁡(l,r−1)≤opt⁡(l,r)≤opt⁡(l+1,r)\operatorname{opt}(l,r-1)\le\operatorname{opt}(l,r)\le\operatorname{opt}(l+1,r)opt(l,r−1)≤opt(l,r)≤opt(l+1,r)

For D[l,r]=C(l,r)+minₗ≤k<r(D[l,k]+D[k+1,r]), Knuth gives opt[l,r−1]≤opt[l,r]≤opt[l+1,r] under the conditions. Set opt[i,i]=i.

Check the boundary. Use a consistent extremal argmin (e.g. largest minimizer) and clamp the upper bound to r−1. Nonnegative interval sums satisfy the conditions; arbitrary matrix-chain multiplication costs depend on k.

Cost O(n²) total time and O(n²) space. The gain comes from summing search-window lengths, not from assuming each interval has a constant number of candidates.

Try one change

For interval [l,r], which two shorter intervals can bound its best split under Knuth's hypotheses?

See the reasoning

[l,r−1] and [l+1,r]. Their chosen optimal splits bracket the new split when the cost satisfies the required monotonicity and quadrangle inequality.

From idea to code

  • Knuth-optimized adjacent merging
    For nonnegative pile weights this interval cost is their sum. Preserve consistent tie breaking when bounding a split by its two neighbours.
Worked C++17 implementation
// Nonnegative pile weights and all costs fitting i64 below INF.
inline i64 merge_cost(const std::vector<int>& a) {
    int n = static_cast<int>(a.size());
    if (n < 2) return 0;
    std::vector<i64> p(n+1);
    for (int i=0; i<n; ++i) p[i+1]=p[i]+a[i];
    std::vector<std::vector<i64>> d(n, std::vector<i64>(n));
    std::vector<std::vector<int>> opt(n, std::vector<int>(n));
    for (int i=0; i<n; ++i) opt[i][i]=i;
    for (int len=2; len<=n; ++len) {
        for (int l=0; l+len<=n; ++l) {
            int r=l+len-1;
            d[l][r]=std::numeric_limits<i64>::max()/4;
            for (int j=opt[l][r-1]; j<=std::min(r-1,opt[l+1][r]); ++j) {
                i64 cost=d[l][j]+d[j+1][r]+p[r+1]-p[l];
                if (cost<=d[l][r]) {
                    d[l][r]=cost;
                    opt[l][r]=j;
                }
            }
        }
    }
    return d[0][n-1];
}
