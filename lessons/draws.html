Cycles in adversarial games need retrograde analysis

Two game positions lead only to each other. Does either player have a forced win?

1. Work one example

Start from positions with known outcomes and work backwards. A move into a losing state certifies a win. A state loses when every move gives the opponent a win. Cycles left unresolved can sustain a draw under infinite-play draw rules.

2. What do we need to remember?

In a cyclic game, first propagate forced wins and losses from terminal states. Unclassified positions can support indefinite play under the stated rules.

3. How do we get the next answer?

In a finite alternating game with normal terminal losses and infinite play declared a draw, process graph states backward. A state is winning as soon as one successor is losing. It is losing when every successor has been proved winning.

W(s)  ⟺  ∃(s→t):L(t),L(s)  ⟺  ∀(s→t):W(t)W(s)\iff\exists(s\to t):L(t),\qquad L(s)\iff\forall(s\to t):W(t)W(s)⟺∃(s→t):L(t),L(s)⟺∀(s→t):W(t)

Initialize zero-outdegree states as losing. Queue solved states; when processing a winning successor decrement the remaining undecided count of each predecessor.

Check the boundary. Seeing a back edge during DFS alone does not prove a draw. Include whose turn it is for asymmetric games and follow the specified rule for infinite play.

Cost O(V+E) on the state graph with reverse adjacency and outdegrees.

Try one change

In a game graph a vertex has one move to a losing vertex and another into a cycle. How is it classified?

See the reasoning

Winning. The player can choose the losing successor. Remaining unresolved cyclic states can be draws only after all forced wins and losses propagate.

From idea to code

  • Topological order and DAG DP
    Use a verified acyclic order. Process every outgoing transition after its source is final. Counting merges by addition and longest paths by maximum.
  • Grundy values on a finite game
    Use mex for a finite impartial normal-play game and XOR for its independent disjoint components. Weighted score games need minimax, while cyclic games may also have draws.

Sometimes the algorithm itself introduces randomness, or a random order turns a big calculation into a sum of indicators.
