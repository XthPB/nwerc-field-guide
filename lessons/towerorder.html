Sort stackable blocks before doing knapsack

Each block has weight, strength and value. It can carry at most its strength above it. Which blocks form the most valuable stable stack?

Work through the choice

Consider adjacent blocks. In an order sorted by increasing weight plus strength from top to bottom, any feasible stack can be rearranged into this order by swapping inversions. Now a new block always goes under the chosen stack. Its strength only needs to support the stored total weight.

The rule you can reuse

Dnew[q+w]=max⁡(Dnew[q+w],Dold[q]+v)for q≤sD_{\rm new}[q+w]=\max(D_{\rm new}[q+w],D_{\rm old}[q]+v)\quad\text{for }q\le sDnew​[q+w]=max(Dnew​[q+w],Dold​[q]+v)for q≤s

Sort by increasing w+s and maintain best value by exact current stack weight. Skipping keeps the old state. Add each block once in descending weight order.

Check the boundary. A high-strength block may still be too heavy for the block underneath it. Always check the weight already above the proposed new bottom block.

Cost O(n log n+nB) for tracked weight bound B, often max(w+s).

From idea to code

  • 0/1 knapsack
    Use the descending capacity loop for one-use items. The initial zeros in this implementation mean “at most this capacity.” For exact weight, mark initially unreachable cells before the first update.
See the idea in contest problems
  • AtCoder DP · Tower

    Sort blocks by increasing weight plus strength. Add a new block underneath only when its strength covers all selected weight above it.
