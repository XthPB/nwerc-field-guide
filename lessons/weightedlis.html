‹ Sequences, scheduling and sweeps

Order the objects you keep · Lesson 33 of 235

Weights, counts, and two strict coordinates

You’re given points with coordinates (x,y) and a reward at each point. You may visit a sequence of points only if both coordinates strictly increase at every step. Find the greatest total reward. A point with the same x as the previous one cannot extend the chain.

1. Work one example

A small ending y helps future moves, but a larger reward helps the objective. Store the best reward by y. Query all points at one x before publishing any result from that x, so tied points cannot follow each other.

2. What do we need to remember?

The most valuable increasing chain does not have to be the longest. Query the best score at smaller ending values.

3. How do we get the next answer?

Sort or sweep the first coordinate. On the second, query the best predecessor from the allowed ranks. For strict first coordinate, query the entire equal-first block before inserting it. Store a source index together with the score for traceback.

d[p]=w[p]+max(0, max d[q] over x[q]<x[p], y[q]<y[p]). For counting longest chains merge (length,count) pairs, adding counts on ties.

Check the boundary. For max and arbitrary replacement/deletion use a segment tree. A prefix-max Fenwick supports monotone increases. Compress equal y to the same rank.

Cost O(n log n) time, O(n) space. If the domain is already ordered and small, a direct array can suffice.

Try one change

A length-three chain earns 6 and a length-two chain earns 15. Both may extend to the next point. Which score do you extend?

See the reasoning

Use 15. The future point adds the same reward to either history, so chain length cannot decide which one dominates.

From idea to code

  • Bottom-up segment tree
    The original combine is addition over a half-open interval. For a min, max, witness or matrix payload, update the stored type, combine and empty identity together. Preserve combination order for matrices.
  • Coordinate compression
    Compression preserves order and equality. Convert open and closed query bounds with lower_bound and upper_bound. Original distances must still use the uncompressed coordinates.
