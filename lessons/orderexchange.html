Find an order that is safe for every chosen subset

Two apps need temporary installation space as well as permanent storage. In which order can they fit on a small phone?

Work through the choice

A large temporary download becomes cheap once installed. Swap a neighbouring pair on paper and compare the peak storage. A safe sorting rule gives one common order for every subset, after which a knapsack can decide which apps to install.

The rule you can reuse

Some selection tasks allow rearrangement and have a peak resource during an operation. Before knapsack, compare adjacent tasks both ways. If one order always needs no more capacity, sort once and run DP over the sorted list.

peak⁡(i,j)=max⁡(pi,si+pj),pi=max⁡(di,si)\operatorname{peak}(i,j)=\max(p_i,s_i+p_j),\qquad p_i=\max(d_i,s_i)peak(i,j)=max(pi​,si​+pj​),pi​=max(di​,si​)

For downloads d and permanent sizes s, let peak p=max(d,s). With prior permanent use U, feasibility is U+p≤C. For order i,j peak is max(pᵢ,sᵢ+pⱼ).

Check the boundary. An exchange argument supplies a common order, but choosing every feasible item greedily can still sacrifice cardinality. Keep minimum permanent use for each installed count.

Cost O(n log n+n²) for count-axis DP, with O(n) space for value alone.

From idea to code

  • 0/1 knapsack
    Use the descending capacity loop for one-use items. The initial zeros in this implementation mean “at most this capacity.” For exact weight, mark initially unreachable cells before the first update.
