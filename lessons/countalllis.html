Count all increasing subsequences by their last value

For the array 1,1,2, how many nonempty strictly increasing subsequences are there if choosing different positions gives different answers?

Work through the choice

Every new position can start a singleton. It can also extend each earlier subsequence ending at a smaller value. Keep a sum of counts by compressed final value. Add the new count at its value, preserving earlier ways ending there.

The rule you can reuse

ci=1+∑j<i, aj<aicjc_i=1+\sum_{j<i,\ a_j<a_i}c_jci​=1+j<i, aj​<ai​∑​cj​

Query a Fenwick prefix ending immediately before the current rank. Add cᵢ at that rank using a point-add Fenwick, or accumulate the value before calling a point-set implementation.

Check the boundary. Equal values cannot extend each other in a strict subsequence. Distinct output strings would require deduplication, whereas this example counts choices of positions.

Cost O(n log n) time and O(n) memory.

From idea to code

  • Fenwick tree
    The original update sets a value and corrects the old contribution. For monotone prefix maxima implement point chmax and prefix max. A prefix maximum cannot be subtracted from another maximum.
  • Coordinate compression
    Compression preserves order and equality. Convert open and closed query bounds with lower_bound and upper_bound. Original distances must still use the uncompressed coordinates.
See the idea in contest problems
  • CSES · Increasing Subsequence II

    Sum counts ending strictly below the current value, add one for the new singleton, then add the result to the compressed value's position.
