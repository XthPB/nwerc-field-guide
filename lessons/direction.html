One decision at a time · Lesson 5 of 235

Dense tabulation, sparse memoization, and rolling layers

You want the edit distance between two strings, but the full table will not fit. Which cells may you overwrite?

1. Work one example

Draw arrows into the cell you are computing. One comes from the left in the current row and two come from the previous row. Two arrays keep all three values available. Saving the old diagonal lets you reuse one array.

2. What do we need to remember?

Picture the rows you actually read when you compute a new row. Only those rows must remain in memory.

3. How do we get the next answer?

Pull only states requested by a recursive transition if reachability is sparse. Build a dense array if nearly every state is touched. Roll an axis only after drawing which older cells a new row reads.

Di=Ti(Di−1)D_i=T_i(D_{i-1})Di​=Ti​(Di−1​)

For a two-row recurrence, compute new = T(old); exchange layers after the complete step.

Check the boundary. A zero value can be a legitimate answer. Use a separate visited flag for memoization. Deep chains may need an explicit stack.

Cost Memoization costs O(reachable states + traversed transitions), plus key lookups. Rolling compresses space and usually discards traceback.
