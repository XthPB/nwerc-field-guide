Keep only reachable descriptions · Lesson 195 of 235

Pack many small capped resources into one array index

You can buy projects, each with a price and known increases to several skill scores. Reach at least 2 in each of three skills for the lowest possible cost. Extra skill above the target is harmless. A score of (2,0,1) and a score of (0,2,1) leave different work to do.

1. Work one example

Cap each skill at the target because future gains are nonnegative. Each of the three digits is now 0, 1 or 2, so there are 27 vectors. A base-three encoding gives a dense lookup without a map of tuples.

2. What do we need to remember?

A few small counters can be encoded together if each has a known range. Decode the counters needed for each legal transition.

Store the minimum cost for each code. For a one-use project read the previous row and update the independently capped coordinates. Precompute transitions when the same gain vector recurs.

Check the boundary. Never use saturation when a later operation can subtract a resource or when exceeding a limit is forbidden. Product-state memory grows exponentially in the number of coordinates.

Cost O(nk·∏(Pᵢ+1)) time and two rows of ∏(Pᵢ+1) costs.

Try one change

Two counters range from 0 to 2 and 0 to 3. How many array cells encode every pair?

See the reasoning

Twelve. The index 4a+b gives each pair its own cell. Test component bounds before incrementing the packed index.

From idea to code

  • 0/1 knapsack
    Use the descending capacity loop for one-use items. The initial zeros in this implementation mean “at most this capacity.” For exact weight, mark initially unreachable cells before the first update.
  • Two-state DP with rolling layers
    Track the best score when the preceding house was skipped or taken. Each step reads the old pair. Adapt it by naming the histories a future move can distinguish.
