Restrict the previous choices · Lesson 150 of 235

Answer “best predecessor of a different colour” with two records

For every new colour c, a transition asks for the cheapest previous state whose colour differs from c. Must you scan all colours for every query?

1. Work one example

Keep the smallest and second-smallest previous records with different colour IDs. If the best record has the forbidden colour, the other record is the answer. If several predecessors have one colour, consolidate that colour first.

2. What do we need to remember?

If the best candidate has the forbidden identity, you need the best candidate with a different identity.

3. How do we get the next answer?

Build the best two once per previous layer and resource count. A same-colour transition, when also allowed, can read that colour directly and use a different resource update.

Check the boundary. If the rule excludes several colours, two records may be insufficient. When only one distinct colour exists, its excluded query is unreachable.

Cost O(C) to build all records per layer, then O(1) per excluded-colour query.

Try one change

The two largest raw scores, 10 and 9, are both red. You must exclude red. What should the data structure have saved?

See the reasoning

The best representative of a different color. Keeping the two largest items without checking their identities can lose the correct answer.

From idea to code

  • Range minimum with the original index
    Sort entries by the query coordinate and keep original IDs. Binary-search a closed coordinate range to obtain a half-open slice. Query its lexicographically smallest (value, ID).
  • Two-state DP with rolling layers
    Track the best score when the preceding house was skipped or taken. Each step reads the old pair. Adapt it by naming the histories a future move can distinguish.
