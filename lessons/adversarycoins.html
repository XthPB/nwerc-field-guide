Can the cashier make an unsplittable payout?

Can a cashier pay 12 cents in coins that two people cannot split equally? The cashier gets to choose the coins.

Work through the choice

First fix a payout and ask if some subset totals 6. Two fives and two ones split. Exchanging the two fives for one ten removes the option of taking just one five. The payout 10,1,1 has no subset worth 6. This explains why bundling helps a search for a counterexample.

The rule you can reuse

A bitset tests a single multiset P. To disprove that every representation of n splits, construct one multiset missing n/2. A one-way exchange preserves such a witness and lets you search a much smaller family.

Reach⁡(P′)⊆Reach⁡(P)h∉Reach⁡(P) ⟹ h∉Reach⁡(P′)\begin{gathered}\operatorname{Reach}(P')\subseteq\operatorname{Reach}(P)\\h\notin\operatorname{Reach}(P)\ \Longrightarrow\ h\notin\operatorname{Reach}(P')\end{gathered}Reach(P′)⊆Reach(P)h∈/Reach(P) ⟹ h∈/Reach(P′)​

If k notes of value d can be bundled into one legal note of value kd, write P′ for the bundled payout. Reach(P′)⊆Reach(P), since each use of the bundle can be replaced by its k constituents. Any missing sum in P remains missing in P′.

Check the boundary. For the euro denominations, bound counts of 1,5,10,50,100 to at most one and counts of 2,20 to at most four. Enumerate these counts and the number of 500s. The residual must be a nonnegative multiple of 200 and fixes that count. Test each candidate’s own bitset independently.

Cost At n≤10000 there are at most 2⁵·5²·(⌊n/500⌋+1) outer choices. Each admitted payout has at most 13+⌊n/200⌋ notes. A dynamic-length bitset takes O(notes·⌈(n/2+1)/word⌉) per candidate. The included C++ uses a fixed 5001-bit row.

From idea to code

  • Find a payout that cannot be split
    The coin values and total bound come from Bisecting Bargain. Test a fixed payout using a half-sum bitset. The enumeration of compressed payouts relies on this particular coin system.
  • Bitset subset sum
    Set only bit zero at the start. A shifted copy represents taking one item. OR retains the outcomes of skipping it. Choose MAXS large enough for the actual largest queried sum.
Worked C++17 implementation
// NWERC 2025 B, 1 <= total <= 10000. An empty result means every payout splits.
inline std::vector<int> unsplittable_payout(int total) {
    if (total % 2) return std::vector<int>(total, 1);
    const std::array<int, 7> low{1, 2, 5, 10, 20, 50, 100};
    const std::array<int, 7> limit{1, 4, 1, 1, 4, 1, 1};
    std::array<int, 7> counts{};
    std::vector<int> witness;
    auto search = [&](auto&& self, int type, int left) -> bool {
        if (type < static_cast<int>(low.size())) {
            for (int k = 0; k <= limit[type] && k * low[type] <= left; ++k) {
                counts[type] = k;
                if (self(self, type + 1, left - k * low[type])) return true;
            }
            return false;
        }
        for (int fives = 0; 500 * fives <= left; ++fives) {
            int rest = left - 500 * fives;
            if (rest % 200) continue;
            std::vector<int> payout;
            for (int i = 0; i < static_cast<int>(low.size()); ++i) {
                payout.insert(payout.end(), counts[i], low[i]);
            }
            payout.insert(payout.end(), rest / 200, 200);
            payout.insert(payout.end(), fives, 500);
            if (!reachable<5000>(payout)[total / 2]) {
                witness = std::move(payout);
                return true;
            }
        }
        return false;
    };
    search(search, 0, total);
    return witness;
}
