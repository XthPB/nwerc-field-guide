‹ Dynamic programming on graphs

Strip trees, then close each cycle

Each vertex points to exactly one successor. Select maximum-weight vertices while never selecting adjacent endpoints of an edge.

Work through the choice

Follow successor pointers until they repeat. Each component has a cycle with trees feeding it. Solve the trees first and then solve the cycle twice, once for each decision at a chosen cycle vertex.

The rule you can reuse

Outdegree one makes every weak component a directed cycle with in-trees. Peel indegree-zero vertices to compute incoming messages. Deal with the remaining cycle by conditioning on its first boundary state and enforcing closure.

opt⁡=max⁡{opt⁡(v0 out),opt⁡(v0 in,vlast out)}\operatorname{opt}=\max\{\operatorname{opt}(v_0\text{ out}),\operatorname{opt}(v_0\text{ in},v_{\rm last}\text{ out})\}opt=max{opt(v0​ out),opt(v0​ in,vlast​ out)}

For weighted independent set on a cycle, solve the linear take/skip recurrence twice: first vertex out, or first in with last forced out. Add the in-tree scores for each state.

Check the boundary. A self-loop forbids selecting that vertex for an independent set. For a two-cycle distinguish duplicated directed edges from two independent undirected constraints. Other tasks need different cycle closure algebra.

Cost O(n) for a constant-state take/skip problem. A boundary with q values may require q runs.

From idea to code

  • Functional graph distances and cycles
    Reuse the tree and cycle decomposition. For a cycle DP enforce consistency between the first and last decisions on the cycle.
  • Rooted tree DP and rerooting
    Use reverse traversal for bottom-up child messages. Use forward traversal for the parent contribution. Derive a new message when the objective differs from distance or subtree size.
