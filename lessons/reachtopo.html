Many reachability queries on a DAG

Many queries ask which vertices one source can reach in a DAG. How do you avoid counting a destination twice along different paths?

1. Work one example

In reverse topological order, form the union of the sets reachable from every outgoing neighbour. A bitset performs many union operations at once. In a diamond the common destination then occupies only one bit.

2. What do we need to remember?

In reverse topological order, union the destination sets of all outgoing neighbors. A bitset represents many target vertices in one state.

3. How do we get the next answer?

Store a bitset of reachable destinations per vertex. In reverse topological order every outgoing neighbour already knows its future. Union those sets. Restrict bit positions to queried targets if only a few matter.

B(u)={u}∪⋃u→vB(v)B(u)=\{u\}\cup\bigcup_{u\to v}B(v)B(u)={u}∪u→v⋃​B(v)

B[u]={u} ∪ ⋃_{u→v} B[v]. For cyclic graphs, first compute the SCC condensation and answer within-component queries separately.

Check the boundary. With 100000 vertices, an all-vertex dense matrix needs about 1.25 GB before overhead. Split target bits into batches or use per-query search when the query set is small.

Cost O((V+E)⌈T/word⌉) word operations and O(V⌈T/word⌉) words for T target bits, or batch for less working memory.

One. Union the two destination sets. Adding the counts of paths would count two routes to that one destination.

From idea to code

  • Topological order and DAG DP
    Use a verified acyclic order. Process every outgoing transition after its source is final. Counting merges by addition and longest paths by maximum.
  • Bitset subset sum
    Set only bit zero at the start. A shifted copy represents taking one item. OR retains the outcomes of skipping it. Choose MAXS large enough for the actual largest queried sum.
