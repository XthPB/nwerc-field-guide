Compress edge-pair transitions by the previous label

Count directed paths whose vertex labels form a Fibonacci-like sequence. What does the last edge tell you about a valid preceding edge?

Work through the choice

On a path ending in labels 2,3,5, the label immediately before 3 must be 2. Group counts ending at each vertex by their previous label. Positive labels give a processing order that finishes predecessor edges before extending them.

Grow Fibonacci paths one edge at a time

1 / 3

Edge 1→2

No predecessor is available. One two-vertex path ends here.

Edge 2→3

The required preceding value is 3−2=1. Extend the earlier path or start fresh, giving 2.

Edge 3→5

The required label is 5−3=2. Both previous paths can extend. The new edge has 3 ways, so all edges together account for 6.

The rule you can reuse

When a path obeys a second-order recurrence on vertex labels, an edge may be the natural state. Replace every predecessor edge with the same required label by one subtotal at its endpoint. A graph containing cycles can still have an acyclic edge recurrence.

D(u,v)=1+bucketu[av−au]D(u,v)=1+\mathrm{bucket}_u[a_v-a_u]D(u,v)=1+bucketu​[av​−au​]

For positive labels, process directed edges (u,v) by increasing aᵤ+aᵥ. ways(u,v)=1+bucket[u][aᵥ−aᵤ]. Then add ways(u,v) to bucket[v][aᵤ]. The 1 counts the two-vertex path.

Check the boundary. From the third label onward, Fibonacci growth strictly exceeds all earlier labels, guaranteeing simple paths here. Zero or negative labels break that argument; a visited-set issue can return.

Cost O(m log m) for sorting, plus O(m) expected hash lookups (or O(m log m) map work). CF 2176D, rated 1800.
