Pack the increments of an LCS row

A conventional longest-common-subsequence table is too slow but its rows increase by only zero or one. Can one bit per column suffice?

Work through the choice

Mark the columns where the row's length rises. For the next character, a bit mask identifies its matching columns. Word shifts and a subtraction propagate which earliest columns can realize the improved lengths.

The rule you can reuse

Adjacent LCS prefix values differ by 0 or 1. Encode these rises as bits. For a new character combine old rises with all its matching positions, then use binary subtraction to retain the earliest feasible rise at each length.

X=SORMx,Y=(S≪1)OR1,S′=XAND¬(X−Y)X=S\mathbin{\mathrm{OR}}M_x,\quad Y=(S\ll1)\mathbin{\mathrm{OR}}1,\quad S'=X\mathbin{\mathrm{AND}}\neg(X-Y)X=SORMx​,Y=(S≪1)OR1,S′=XAND¬(X−Y)

Least significant bit corresponds to the first position of B. Let X=S OR matchMask[ch], Y=(S≪1) OR 1. S′=X AND NOT(X−Y), using fixed-width unsigned arithmetic. The answer is popcount(S).

Check the boundary. Across words propagate both the shift carry and subtraction borrow. A library bitset with only &, |, shifts and no subtraction does not directly implement this recurrence.

Cost O(n⌈m/word⌉) word operations, O(alphabet·⌈m/word⌉) match masks. A witness requires extra reconstruction.

From idea to code

  • Longest common subsequence and interval order
    The sheet gives the LCS recurrence and interval iteration order as notes. For an LCS witness store a parent choice or compute forward and backward rows for a recursive split.
  • Bitset subset sum
    Set only bit zero at the start. A shifted copy represents taking one item. OR retains the outcomes of skipping it. Choose MAXS large enough for the actual largest queried sum.
