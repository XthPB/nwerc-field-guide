Revisit graphs with a richer state · Lesson 84 of 235

Track visit parity even when a walk revisits vertices

A walk on a small graph must visit one vertex an odd number of times and another an even number. How do you find the fewest visited positions?

1. Work one example

Entering a vertex flips its parity bit. A revisit can be required, so the mask may lose a set bit. Mask size no longer provides a valid DP order. In the unweighted expanded graph, BFS supplies the order by shortest walk length.

2. What do we need to remember?

Each visited vertex flips its own bit. A state needs the full mask of odd-visit vertices together with the current endpoint.

3. How do we get the next answer?

(u,M)→(v,M⊕2v)for every edge u→v(u,M)\to(v,M\mathbin{\oplus}2^v)\quad\text{for every edge }u\to v(u,M)→(v,M⊕2v)for every edge u→v

For a free start, initialize every singleton walk with distance one. Allow the empty walk as a separate answer of length zero for mask zero if the statement permits it.

Check the boundary. A standard visit-all subset transition always adds a new vertex. Here toggling can revisit an earlier mask, so processing masks by population count fails.

Cost O((n+m)2ⁿ) time, O(n2ⁿ) distance storage.

Try one change

Starting with an empty visit mask, what mask remains after visiting A, then B, then A?

See the reasoning

Only B is odd. Toggle the bit on every visit. The endpoint A is a separate fact needed to list the next legal moves.

From idea to code

  • Held–Karp path or closed tour
    Set the start city to zero. The two switches in the calling convention are the distance matrix and whether the last edge must return to the depot. For a fixed finishing city read that one endpoint.
  • Dijkstra on an expanded graph
    First define what constitutes a vertex of the state graph. Construct an edge for each legal transition. All weights used by Dijkstra must be nonnegative.
