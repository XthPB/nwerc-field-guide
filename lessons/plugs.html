‹ Grids and narrow frontiers

Occupancy fails when the frontier must remain connected

A narrow grid must contain one connected loop. Is it enough to remember which frontier edges are occupied?

Work through the choice

Four loose ends can already be joined in different pairs behind the frontier. Connecting two ends now may close a loop immediately or just join separate paths. Record which ends belong to the same unfinished component.

The rule you can reuse

A frontier can have the same occupied cells with different pairings of unfinished paths. Record connectivity labels and local degrees when constructing one cycle, one path or a connected set. Canonicalize labels after every move.

state=(occupied ports, partition into connected components)\text{state}=(\text{occupied ports},\ \text{partition into connected components})state=(occupied ports, partition into connected components)

At a new cell, create, continue or merge components according to incoming and outgoing edges. Close a loop only at the permitted final stage for a single-cycle problem.

Check the boundary. Renaming labels must leave the key unchanged. Reject a component that disappears before completion when all vertices must belong to one component.

Cost O(cells × number of canonical states × local transitions). Arbitrary partitions grow like Bell numbers; planarity can restrict states to noncrossing partitions.

From idea to code

  • Enumerate submasks
    The loop visits every nonempty submask. Add the empty option separately if it is legal. Enumerating submasks for every mask costs three to the power n across all masks.

    This snippet merges ordinary components. A frontier DP additionally needs a canonical encoding of connectivity on its active boundary. A fresh temporary DSU can compute a transition.
