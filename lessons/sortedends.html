‹ Interval and partition DP

Sort the values and undo the last extreme

Arrange 1, 4, 5 and 10 in an order that minimizes the sum of the ranges seen after each insertion. The order 4, 5, 1, 10 pays 0 + 1 + 4 + 9. How can you prove you only need intervals of sorted values?

Work through the choice

Consider an optimal order whose last value lies strictly between its minimum and maximum. Find whichever extreme appeared later, and swap it with the final interior value. Between these two positions the old prefixes already contained both extremes. Their ranges can only shrink after the swap. Therefore some optimum ends with an extreme. Removing it leaves exactly the same problem on a shorter sorted interval.

The rule you can reuse

D(l,r)=ar−al+min⁡ ⁣(D(l+1,r),D(l,r−1))D(l,r)=a_r-a_l+\min\!\big(D(l+1,r),D(l,r-1)\big)D(l,r)=ar​−al​+min(D(l+1,r),D(l,r−1))

Sort first and use zero for singletons. Fill by increasing interval length. For each interval, the last insertion charges its full width regardless of which endpoint arrived last. Save that endpoint when you want to reconstruct the order in reverse.

Check the boundary. Sorting here describes which values remain. The insertion order itself can start in the middle. The exchange proof uses the prefix range objective. A penalty depending on the identities or arrival order of interior values needs its own argument.

Cost O(n²) time and O(n) working memory for the optimal cost. Keep O(n²) decisions for straightforward reconstruction.

From idea to code

  • Undo the last extreme of a sorted interval
    The cost is the sum of ranges of all prefixes of a chosen order. This implementation sorts a copy, so equal input values remain separate items.
  • Interval DP in increasing length
    Use the increasing-length loop for two smaller intervals. Supply the base cases, valid split positions, immediate cost and choice of min, max or sum from the problem.
