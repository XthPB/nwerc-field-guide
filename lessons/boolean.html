Choose objects once or many times · Lesson 11 of 235

Which sums can you make using each item once?

You have a list of item weights and a target weight. You may use each physical item once, and you want to know whether some selection totals the target exactly. If the only item weighs 3 and the target is 6, using the same item twice would give a wrong answer.

1. Work one example

Start with just sum zero. Every old sum has two choices. Leaving the item behind preserves it. Taking it adds 3. Updating from high sums to low sums keeps the newly reached 3 from being used again this round.

2. What do we need to remember?

One entry answers whether any choice of the items processed so far makes exactly this total.

3. How do we get the next answer?

Each item has one opportunity to contribute. Group choices by the last item and store reachable exact sums. If maximizing value under a capacity, an at-most table can instead start at zero everywhere when choosing nothing is legal.

R0={0},Ri=Ri−1∪{s+wi:s∈Ri−1}R_0=\{0\},\qquad R_i=R_{i-1}\cup\{s+w_i:s\in R_{i-1}\}R0​={0},Ri​=Ri−1​∪{s+wi​:s∈Ri−1​}

R₀={0}. Rᵢ = Rᵢ₋₁ ∪ {s+wᵢ : s∈Rᵢ₋₁}. For exact max-value use −∞ for every unreachable positive weight.

Check the boundary. Update sums in descending order for positive one-use weights. For Boolean queries, answer exact target directly or scan down for the best achievable sum ≤ cap.

Cost O(nW) time, O(W) cells. Weights larger than W can be skipped for positive-weight exact-sum queries.

Try one change

One physical coin is worth 3. Should 6 become reachable when processing it?

See the reasoning

No. Read the old total 3 before it can be set by the same coin. A descending sum loop does this in one array.

From idea to code

  • 0/1 knapsack
    Use the descending capacity loop for one-use items. The initial zeros in this implementation mean “at most this capacity.” For exact weight, mark initially unreachable cells before the first update.
  • Bitset subset sum
    Set only bit zero at the start. A shifted copy represents taking one item. OR retains the outcomes of skipping it. Choose MAXS large enough for the actual largest queried sum.
