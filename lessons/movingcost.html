Evaluate a moving segment cost instead of recomputing it

A segment costs one for each pair of equal letters. How do you answer many related candidate-segment costs cheaply?

Work through the choice

Keep a window and the frequency of every letter inside it. Adding an a forms one new pair with every existing a. Removing an a undoes pairs with every remaining a. Move the endpoints as the optimized DP requests costs.

The rule you can reuse

Some partition costs admit O(1) add/remove at either end. Maintain one active [l,r], its frequency table and the accumulated statistic while the optimization asks for different intervals. Charge pointer travel over the actual evaluation order.

C(l,r+1)=C(l,r)+freq⁡[l,r](ar+1)C(l,r+1)=C(l,r)+\operatorname{freq}_{[l,r]}(a_{r+1})C(l,r+1)=C(l,r)+freq[l,r]​(ar+1​)

For equal-pair cost C=Σₓ choose(freq[x],2), adding x increases cost by freq[x] before increment. Removing x decreases it by the new frequency after decrement.

Check the boundary. An O(1) single shift does not make an arbitrary range query O(1). For the usual monotone split recursion with ordered candidate scans, bound movement by O(n) per recursion depth per layer.

Cost O(Kn log n) pointer moves and candidate evaluations in the standard schedule. Rank compression speeds up the frequency updates.

From idea to code
