A stochastic process can reduce to choosing a deterministic order

A tree vertex changes colour when a randomly checked neighbour already has the desired colour. Which vertex should you attempt next to minimize the expected time?

Work through the choice

With d neighbours of which r qualify, each attempt succeeds with probability r/d. Repeated attempts at that chosen vertex therefore cost d/r in expectation while the configuration stays fixed. Changing a vertex alters those prices for its neighbours, creating an ordering problem.

The rule you can reuse

For tree recolouring, select a black vertex with r red neighbours among d. Its first successful recolouring has expected waiting cost d/r if you keep trying. A failed attempt leaves the state unchanged, so the first-step optimality equation lets you take the best such action and repeat it. Selecting an already-red vertex cannot improve the optimum since losing red only removes opportunities.

E[attempts until success]=1r/d=dr(r>0)\mathbb E[\text{attempts until success}]=\frac1{r/d}=\frac{d}{r}\quad(r>0)E[attempts until success]=r/d1​=rd​(r>0)

Choose an order to turn black vertices red. Orient each black–black edge from earlier to later; any orientation of a tree is acyclic. A node’s cost depends only on the number of earlier neighbours, including initially red ones.

Check the boundary. For each parent-before/after state, each black child offers a cost for before and after the current node. Account for forced choices, sort the finite differences, and try each possible number of earlier children with a prefix sum. Exclude r=0. Initially red vertices are already earlier and split the black forest.

Cost O(n log n) for the tree DP using sorting at each node. Use a representation appropriate to the statement’s numerical output. CF 2219C, rated 2300.
