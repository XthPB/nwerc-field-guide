‹ Knapsack and subset sum

When the capacity is huge, index by profit

A bag holds 7. Three items have weight and profit (8,3), (3,2), (4,2). What profit fits?

Work through the choice

Try asking how light a selection earning a fixed profit can be. Profit 4 costs only 7 by taking the last two items. For equal profit the lighter choice always has at least as much room for the future.

The rule you can reuse

If weights or the budget can reach 10⁹, estimate the sum of values. For each exact total value retain the least weight needed. All heavier ways to earn that same value have identical future options or fewer under an upper weight limit.

mi(v)=min⁡{mi−1(v), wi+mi−1(v−pi)}m_i(v)=\min\{m_{i-1}(v),\,w_i+m_{i-1}(v-p_i)\}mi​(v)=min{mi−1​(v),wi​+mi−1​(v−pi​)}

m[0]=0, m[v>0]=∞. For an item (w,p), m[v] ← min(m[v],m[v−p]+w), descending in v.

Check the boundary. Works with nonnegative integer values and an upper capacity. If both axes are huge, try a Pareto frontier or split-and-join.

Cost O(nΣv) time, O(Σv) memory. Minimum cost for exactly k selected items uses the same inversion with k as axis.
