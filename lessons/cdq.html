A third coordinate and earlier-to-later transitions

Find the longest chain when three different coordinates must all increase. How do you enforce all three without a cubic table?

1. Work one example

Order by the first coordinate. During a divide-and-conquer merge, already solved points in the left half can update the right half. Sweep by the second coordinate and query a prefix tree on the third. Handle equal coordinates according to strictness.

2. What do we need to remember?

Divide the processing order in half. Apply cross-half contributions after left states are ready and before finalizing the right states.

3. How do we get the next answer?

When a transition requires several inequalities, sort one dimension and accelerate cross-half contributions. For DP, finish the left recursion before relaxing left→right and recurse right only after those contributions arrive.

In x order: solve(left); sweep left and right events by y while a Fenwick tree on z answers prefix maxima; undo updates; solve(right).

Check the boundary. Keep recursion ranges in their true topological order and batch equal x when x must increase strictly. A static dominance count can reorder work differently from a DP dependent on fresh scores.

Cost Typically O(n log² n) with comparison sorts and a Fenwick per merge, O(n) working memory with reused buffers and cleanup.

Try one change

Why process cross-half transitions from the earlier half to the later half before solving the later half fully?

See the reasoning

Later states may improve using those earlier states and then affect each other. They need the incoming improvements before their own transitions are finalized.

From idea to code

  • Fenwick tree
    The original update sets a value and corrects the old contribution. For monotone prefix maxima implement point chmax and prefix max. A prefix maximum cannot be subtracted from another maximum.
  • Coordinate compression
    Compression preserves order and equality. Convert open and closed query bounds with lower_bound and upper_bound. Original distances must still use the uncompressed coordinates.
