‹ Advanced range queries inside DP

Store a witness or the number of optimizers inside each range node

A range contains multiple equally good predecessors. Return their best score, their total number of ways and one actual route.

Work through the choice

Define the value stored in every tree node. When combining unequal scores keep the better record. On a tie add the counts and choose a consistent representative index. Disjoint query pieces then combine in the same way as tree children.

The rule you can reuse

The index range selects eligible predecessors. The payload decides what is retained from those predecessors. For a maximum score with count and witness use a value, multiplicity and representative original index.

(v,c,i)⊕(v,d,j)=(v,c+d,min⁡(i,j))(v,c,i)\oplus(v,d,j)=(v,c+d,\min(i,j))(v,c,i)⊕(v,d,j)=(v,c+d,min(i,j))

On unequal values keep the higher. On equal finite values add counts and choose a fixed witness such as smaller index. Use a genuinely empty identity such as (−∞,0,none). Initialize a single empty path once if the recurrence allows a new start.

Check the boundary. A conventional overlapping sparse-table RMQ works for min, max and idempotent pairs such as (score,id). It double-counts a shared optimum with this count payload. A segment tree or disjoint sparse table combines disjoint pieces.

Cost A mutable segment tree uses O(log n) per operation. An associative static disjoint sparse table can use O(1) queries after O(n log n) preprocessing. Ordinary prefix subtraction requires the right inverse operation.

From idea to code

  • Merge optimal scores and counts
    Extend the winning score, sum tied counts modulo the modulus and preserve one witness. Combine disjoint sources so a path never counts itself twice.
  • Bottom-up segment tree
    The original combine is addition over a half-open interval. For a min, max, witness or matrix payload, update the stored type, combine and empty identity together. Preserve combination order for matrices.
