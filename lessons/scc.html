‹ Dynamic programming on graphs

Solve cycles locally and connect the components

A directed route may enter a cycle at a and leave at b. Can the entire cycle be represented by one reward?

Work through the choice

Collapse mutually reachable vertices to reveal the acyclic order between components. Then examine the rule inside a component. If every vertex must be visited at most once, entering and exiting at fixed vertices can change which rewards you collect.

The rule you can reuse

Condensation is a DAG. Contract an SCC to one value only when entry and exit details cannot affect future gain. If components are tiny, solve the internal entry-to-exit problem exactly and expose a transfer table.

Dexit(v)=max⁡u∈C{Denter(u)+TC(u,v)}D_{\rm exit}(v)=\max_{u\in C}\{D_{\rm enter}(u)+T_C(u,v)\}Dexit​(v)=u∈Cmax​{Denter​(u)+TC​(u,v)}

For component C use T_C[u,v] for best internal path entering u, leaving v. Combine incoming scores with T_C, then relax outgoing component edges.

Check the boundary. Many revisits plus collectible-once positive rewards can permit taking the sum of an SCC. Longest simple path generally cannot. A bound on cycle length alone need not bound SCC size for arbitrary graphs.

Cost Condensation O(V+E), plus the cost of the internal tables. For component size b, simple paths can use O(b²2ᵇ) per fixed start.

From idea to code

  • Strongly connected components
    Build a condensation DAG and define what one component contributes. A simple path with restricted entry and exit may need its own internal subproblem.
  • Topological order and DAG DP
    Use a verified acyclic order. Process every outgoing transition after its source is final. Counting merges by addition and longest paths by maximum.
