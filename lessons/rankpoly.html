Count by rank instead of remembering actual labels

Fill three positions with the distinct numbers 1, 2 and 3. The first value must be smaller than the second, and the second larger than the third. Count the valid permutations. A longer input supplies a whole sequence of required rises and falls.

1. Work one example

Actual labels matter only by relative order. Keep the rank of the last element among the values already used. Inserting a new last value converts the inequality into a prefix or suffix sum of old ranks.

2. What do we need to remember?

Remember the rank of the last value among the used labels. Inserting the new final rank shifts the old rank by a known amount.

3. How do we get the next answer?

For up/down patterns in a permutation, only the rank of the last element among currently used values matters. Insert the new final rank and shift the ranks of earlier values above it. Clean inequalities turn into prefix or suffix sums.

For i values ranked 0…i−1, append rank j∈[0,i]. An up-step sums previous ranks k<j; a down-step sums k≥j. Start with length 1 and count 1.

Check the boundary. This symmetry uses relative comparisons only. An absolute constraint such as “the first value is exactly 7” may require an additional state. Distinguish ties when labels repeat.

Cost O(n²) time with row prefix sums, O(n) memory, versus an O(n³) direct sum.

Try one change

If a new last element has rank 2 among three elements, which previous ranks can sit below it?

See the reasoning

Only previous rank 1. Inserting rank 2 shifts the old rank 2 up to rank 3. Count the allowed previous ranks with this shift in mind.
