Read dynamic programming in order

Begin with two routes and one decision. Each stage adds a question the previous techniques could not yet answer.

Start the first lesson Browse the stages

Four words used throughout the guide
State
The question one cell answers. For example, “What is the best score if my last card is red?”
Transition
One legal move between cells. Playing a blue card changes the last color to blue and adds its reward.
Base case
An answer you know before taking a move. With no cards played, the score is zero.
Witness
The actual choices that achieve the answer, such as the sequence of cards. A score by itself does not identify them.

Part 1 of 6

Build your first table

Start with one decision. Ask what must survive it, write the smallest useful table, and recover one actual choice.

One decision at a time1–5

Two routes can reach the same place with different futures. Work out which detail must distinguish them before choosing a formula.

  1. What must a state remember?
  2. A fixed number of recent decisions
  3. Can I, how many, how good, and how many best?
  4. Find a quantity that always moves forward
  5. Dense tabulation, sparse memoization, and rolling layers
Follow a prefix6–10

Once a prefix has an answer, try extending it by one element. Sometimes the best answer ends here, and sometimes it ended earlier.

  1. Kadane’s algorithm and the best subarray ending here
  2. Before, inside, and after an operation
  3. Query an interval of previous values
  4. Count previous prefixes with the missing sum
  5. Count choices on both sides of a middle position
Choose objects once or many times11–16

A number line turns picking objects into reaching totals. Change one rule about reuse and watch the loop order change.

  1. Which sums can you make using each item once?
  2. Identical weights, distinguishable items, and multiplicity
  3. Reuse, bounded stock, or one choice per group
  4. Count bounded allocations with one sliding sum
  5. When do all subset sums form one interval?
  6. Retrieve the selected items from a compressed sum table
Add one more coordinate17–22

The sum alone can hide a constraint. Add one coordinate, estimate its cost, then ask whether a conservation law can remove it.

  1. Estimate the actual array before choosing a technique
  2. Build a state by asking which histories can have different futures
  3. Two independently advancing strings make a 2D grid
  4. Delete a coordinate using a conservation law
  5. Saturate, sparsify or pack a large product of dimensions
  6. One witness, all optima, and lexicographic rank

Part 2 of 6

Find the shape of the subproblem

The steps of a route, the ends of a string, and the boundary of an interval suggest different ways to divide the work.

Walk across a grid23–29

Row and column give a natural order. Add direction, residue, or another traveler only when the next move needs that fact.

  1. Separate a monotone walk from a general shortest path
  2. Find the largest all-filled square by its bottom-right corner
  3. Count paths with a limited number of turns
  4. Carry a remainder along a constrained grid walk
  5. Minimize trailing zeros on a path, including zero cells
  6. Keep an entire diagonal of equally good prefixes
  7. Synchronize two paths by elapsed moves
Order the objects you keep30–36

Two prefixes of the same length can have very different prospects. Keep the most useful ending and use it to extend a chain.

  1. Keep a frontier when one score per position fails
  2. The cheapest tail for each length
  3. Count all increasing subsequences by their last value
  4. Weights, counts, and two strict coordinates
  5. Sort by finish and jump to the last compatible predecessor
  6. Find an order that is safe for every chosen subset
  7. Sort stackable blocks before doing knapsack
Read two strings together37–44

Begin with the choice to match or skip. Then reconstruct a witness, add another cursor, or exploit the special structure of the matches.

  1. Two prefixes and the last alignment column
  2. Recover a shortest string containing both inputs as subsequences
  3. Count a fixed pattern inside a stream
  4. Dictionary breaks, trie edges, and weighted parsing
  5. Fit three growing strings inside a host
  6. Three independently depleted piles give three prefix indices
  7. Common order in two sequences plus increasing values
  8. Carry the longest relevant suffix
Cut the last piece45–52

A final cut produces a solved prefix. A final split inside an interval produces two solved intervals. Decide which description your problem permits.

  1. Exactly k consecutive pieces
  2. Know when a segment contains every copy of its values
  3. Sort the values and undo the last extreme
  4. Split on the final merge, pivot, or triangle
  5. Choose a matrix parenthesization by the last multiplication
  6. Two ends, score difference, and forced turns
  7. Let matching endpoints join a palindrome deletion
  8. Delete, paint, or merge matching endpoints
Describe a graph walk53–57

Elapsed edges, visited intermediates, or an increasing label can give graph states an order. Find that order before treating a cycle as a recurrence.

  1. Use shortest distances to expose a DAG of optimal paths
  2. Fix the number of moves to make a cyclic graph acyclic in time
  3. Index a shortest-path DP by the intermediates it allows
  4. Expand a graph by the small missing state
  5. A pairwise edge price needs a pending first edge

Part 3 of 6

Use structure to shrink the search

Having written a recurrence, identify the dimension that actually limits the input. A bitset, a mask, a separator or a tree edge can replace the original search.

Shrink the knapsack axis58–67

A capacity too large for a table may still have a small total value, few distinct shifts, or a narrow excess over a common weight.

  1. Update many reachable sums with one shift
  2. When the capacity is huge, index by profit
  3. Cardinality, two budgets, and resource coupling
  4. Negative weights, balance, residues, and nonempty subsets
  5. Partition, complements, gcd, and smallest missing sum
  6. Remove a shared weight before indexing the capacity
  7. Repeated weights and the square-root bound
  8. Solve a small geometric instance first, then knapsack its cost curve
  9. Which voting groups need every member?
  10. Can the cashier make an unsplittable payout?
Cut the search in half68–73

When the values are huge but the object count is small, enumerate two halves. Derive exactly what makes one half compatible with the other.

  1. Choose the parameter before you split
  2. Join two lists of subset sums
  3. Closest, at most, or inside an interval
  4. Profit under capacity, several resources, and exact size
  5. Meet on a grid, a hash, or a boundary state
  6. When the two halves interact through conflicts
Choose a set and its endpoint74–83

A mask records which objects have been used. Only add an endpoint, a phase, or a partition of the mask when the next move can observe it.

  1. An exact set can determine the step number
  2. A lexicographic pair can replace enumeration of groups
  3. Visit every city with a set and a last stop
  4. A route can stop, return, visit only terminals, or respect prerequisites
  5. Geometry can determine the price of a combinatorial move
  6. Pack all possible Hamiltonian endpoints into one mask
  7. Track prime parity, used primes, or small-feature coverage
  8. Partition a set into compatible groups
  9. Charge a pair whenever a growing cut separates it
  10. All submask aggregates by one sweep per bit
Revisit graphs with a richer state84–88

Some walks revisit a vertex with new information. Track a mask when visits change the future, or compress cycles before propagating through the graph.

  1. Track visit parity even when a walk revisits vertices
  2. Solve cycles locally and connect the components
  3. Many reachability queries on a DAG
  4. Strip trees, then close each cycle
  5. Compose a score while jumping through a functional graph
Pass one message up a tree89–95

The parent can see a child subtree through one edge. Decide what the child must report, then combine the reports without reusing a child.

  1. A tree edge is a one-vertex interface
  2. At most one child can take a special edge
  3. Collapse an interval of allowed labels to its endpoints
  4. Choose tree edges with a different degree quota at each vertex
  5. Keep a path open for the parent or close it through this vertex
  6. Merge a child’s size or budget distribution
  7. A prerequisite tree can become a linear jump DP
Ask the same tree question everywhere96–100

After the upward pass, send the missing outside information back down. Each child receives a message that excludes its own contribution.

  1. Send messages in both directions
  2. Send each child the contribution of all its siblings
  3. Reroot a sum of squared distances
  4. Answer a subtree query after changing the root
  5. Sparse marked vertices and virtual-tree DP
Follow tight bounds digit by digit101–112

Once a prefix falls below a bound it becomes free. Add memory for the actual digit rule, leading zeros and the output you want to accumulate.

  1. Translate an enormous numeric interval into a short string
  2. Make leading zeros and the actual number zero behave correctly
  3. Handle a bound with ten thousand decimal digits
  4. Sum digits, sum values, or compute moments without a sum axis
  5. Construct the k-th number satisfying a digit rule
  6. Attach a residue, digit mask, position, or automaton
  7. Digit products can return from above the limit
  8. Count bounded numbers avoiding a digit pattern
  9. Choose and order actual digits
  10. Change direction for arithmetic carries
  11. Count bounded pairs whose binary addition has no carry
  12. Classify a large binary number by its popcount

Part 4 of 6

Count outcomes and choices

Move from the best single answer to all possibilities. The work now is keeping multiplicities, dependencies and stopping decisions straight.

Count each object once113–118

A canonical witness removes double counts. Use it to subtract overlaps, count divisor classes, and insert objects into a growing arrangement.

  1. Charge each object to a unique last choice
  2. Count the complement using a canonical first violation
  3. A divisor lattice is another DP order
  4. Close a fixed divisor target under harmless additions
  5. Count by rank instead of remembering actual labels
  6. Count permutations with exactly k inversions
Measure a random process119–126

Start by distributing mass over outcomes. Turn that distribution into an expectation, then solve the extra equations introduced by retries and memory.

  1. Follow probability through one trial at a time
  2. First-step analysis and self-loops
  3. Several mutually dependent expectations
  4. When a random gcd can stay where it is
  5. Track only the moments a nonlinear reward reads
  6. Change the objective by tracking its incremental expected reward
  7. A random walk can have an acyclic direction and a cyclic row
  8. Count interchangeable species and condition on a real change
Choose while the future is uncertain127–133

At each state compare acting and stopping. Information from earlier observations can change the future distribution, or the opponent can choose the next branch.

  1. Choose before or after observing a random outcome
  2. Decide whether to keep a reward or try once more
  3. Learn an unknown probability as you make decisions
  4. Recover the most likely hidden state sequence
  5. Winning positions, minimax, and sums of independent games
  6. When one move splits a game in two
  7. Cycles in adversarial games need retrograde analysis
Track more than the last character134–141

When the next symbol depends on a suffix or unmatched openings, replace the full string by its relevant boundary description.

  1. Count wildcard bracket strings by their open balance
  2. Jump over a balanced suffix to find its opening bracket
  3. Different subsequences, next occurrences, and ranking
  4. Restrict edit distance to a diagonal band when only k edits matter
  5. Only matching pairs can improve LCS
  6. A witness from two thin rows
  7. Rank distinct substrings by counting paths in a suffix automaton
  8. Palindrome boundaries, suffix links, and series links
Cross a narrow boundary142–147

Some boards are huge in length but small in width. Start with occupied cells, then add connectivity when a future placement can notice it.

  1. Paint column runs with a minimum and maximum width
  2. A narrow frontier remembers occupied cells
  3. Count towers by the seam at their top
  4. Occupancy fails when the frontier must remain connected
  5. Replace a narrow strip by a small separator
  6. Four boundaries identify an arbitrary subrectangle

Part 5 of 6

Make a correct recurrence fast

Start with the slow transition. The shape of its eligible predecessors tells you which query, sweep, or algebraic shortcut can replace the inner loop.

Restrict the previous choices148–155

Write down exactly which previous states qualify. Their shape determines whether you need a sliding window, two ranges or an index attached to a score.

  1. A moving predecessor window with a monotone deque
  2. Search by one coordinate and return the best of another
  3. Answer “best predecessor of a different colour” with two records
  4. A forbidden gap can turn one predecessor query into two
  5. Store a witness or the number of optimizers inside each range node
  6. Use higher barriers to bound possible jumps
  7. Accumulate range rewards between the few times a state can change
  8. Independent rectangle bounds require a second range dimension
Maintain the split candidates156–164

Advancing the right endpoint can update many old cuts at once. Group cuts that change together, then consider versions when updates branch in time.

  1. A new endpoint changes many split candidates by the same amount
  2. Equal segment extrema form consecutive blocks of cuts
  3. Remove a large multiplicity with a residue-class deque
  4. Versions or time intervals preserve the correct DP layer
  5. Find the k-th value between two array positions
  6. A range update can act linearly on each stored DP value
  7. Represent a substring by its whole DP transition
  8. Replace a fan of interval transitions with segment-tree nodes
  9. A third coordinate and earlier-to-later transitions
Recognize a cost matrix165–168

When many rows ask for a best column, prove how the optimizer moves. Distinguish monotone optimal indices from the stronger property used by SMAWK.

  1. Evaluate a moving segment cost instead of recomputing it
  2. Why the best partition cut moves to the right
  3. Bound the split between two shorter intervals
  4. A totally monotone transition matrix
Turn costs into lines or slopes169–174

Expand a transition before choosing a data structure. A linear expression, a trial penalty, and discrete convexity lead to different shortcuts.

  1. Turn each predecessor into a line
  2. An envelope with arbitrary insertions or query order
  3. Optimize a ratio by subtracting a trial price
  4. Trade a prescribed count for a penalty
  5. Carry a convex piecewise-linear cost function
  6. Represent a convex tree DP by its sorted marginal costs
Compose transitions175–180

Repeated moves can be composed in blocks. Introduce matrix powers before fast recurrences, then bring in polynomial and subset convolutions.

  1. Maintain a composition when positions change
  2. Exponentiate a repeated stationary transition
  3. Jump to the n-th term of a short linear recurrence
  4. Convolve independent count distributions
  5. OR, AND, XOR, and subset convolution are different joins
  6. Combine two functions on disjoint subsets

Part 6 of 6

Combine the ideas under contest constraints

The last stages mix families. Identify the ordinary recurrence first and then the extra observation that makes it work on this input.

Count paths without visiting every cell181–186

Replace a dense grid by obstacles, event points or symmetry classes. Where paths interact, record how many joint choices the boundary leaves.

  1. Count lattice paths that stay below a diagonal
  2. Sparse obstacles and a first-bad-event subtraction
  3. Index a lattice DP by move counts when coordinates are huge
  4. Replace a huge symmetric board by four probability or count states
  5. Count vertex-disjoint lattice paths using a determinant
  6. Four directional path tables can meet around a crossing
Make geometry part of the state187–192

Order points or cut a polygon to make the geometry acyclic. For costs based on distance, transform the coordinates or the transition itself.

  1. Replace strict geometric containment with a chain
  2. Turn a reachability cone into coordinate inequalities
  3. Compute the cheapest Manhattan delivery to every grid cell
  4. Absolute distance can turn all predecessors into two sweeps
  5. Choose the triangle incident to a boundary chord
  6. Two monotone chains replace a visited set
Keep only reachable descriptions193–198

Merge arithmetic states with equal futures, pack a few coordinates, or count the compressed state of another DP when the objects themselves are too numerous.

  1. Equivalent suffixes under gcd, AND, or OR
  2. Memoize only the quotients you can actually visit
  3. Pack many small capped resources into one array index
  4. Index by moves when the answer is smaller than the search space
  5. Count inputs that produce the same DP state
  6. Enforce an XOR bound on every pair in a subset
Split, merge, or temporarily omit199–208

Return to intervals and tree subproblems with richer boundaries. A conditional merge, a central separator, or an outside knapsack can make repeated work affordable.

  1. Keep the group that will merge with an interval boundary
  2. Noncrossing pairs, parsing, and interleaving
  3. Count deletion orders by interleaving independent regions
  4. Cut a circular instance at a justified boundary
  5. Make a range minimum or maximum the root
  6. Merge secondary structures from smaller subtree into larger
  7. Pair paths through one separator exactly once
  8. A transitive closure can make the entire SCC collectible
  9. Few terminals, many ordinary graph vertices
  10. Build the knapsack of everything except one item
Use a second algorithm inside DP209–213

Test a proposed answer, accelerate a string recurrence with bits, or undo a counting transition. Check the extra invariant required by the faster method.

  1. Binary search the answer with a DP feasibility test
  2. A threshold leaves an additive budget and a sliding predecessor interval
  3. Separate frequent and rare transition sizes
  4. A count-generating function can support item deletion
  5. Pack the increments of an LCS row
Reason about random choices214–218

Distinguish how a random priority splits a subproblem, how a distribution can be sampled exactly, and when random colors or fingerprints preserve the desired event.

  1. Replace a random elimination order with random priorities
  2. Use completion counts to sample a valid answer uniformly
  3. Fix random decisions one at a time while preserving an expectation
  4. Randomly colour vertices, then run an exact subset DP
  5. Evaluate a counting polynomial when only identity matters
Choose a state in unfamiliar problems219–227

Follow a changing bound backward, track which roles can still be filled, and use a separator or ladder of thresholds to reconstruct a feasible solution.

  1. Undo an invertible decision chain
  2. Quotient rounding can leave only two states per depth
  3. A cap on the maximum becomes bounded denomination stock
  4. Compress edge-pair transitions by the previous label
  5. A predecessor must become eligible before a range maximum can see it
  6. One family of intervals contributes a ramp at every covered index
  7. Only four witnesses determine a geometric score
  8. Exact nearest-point distances turn into clauses on adjacent surviving sites
  9. Summarize a deterministic subtree traversal that resets its own memory
Finish with counting and optimization hybrids228–235

Move from ordered shapes to counting patterns, piecewise recurrences and linear information. Each final example asks which earlier state design survives the combination.

  1. Sort events and count open groups
  2. Turn “all pairs are compatible” into a chain through each object
  3. A stochastic process can reduce to choosing a deterministic order
  4. Count strings that contain every allowed subsequence
  5. Expand a square and factor the coefficient of a pair
  6. Classify vertices by the complete paths that contain them
  7. Move a tree-cut DP into the XOR span of allowed totals
  8. Build a long DP row by reusing slices
