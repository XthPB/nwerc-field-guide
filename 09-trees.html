Dynamic programming on trees

Four vertices form a path, numbered 0, 1, 2 and 3. Choose each in turn as the starting vertex and add its distances to all four vertices. How can you get all four totals without four independent searches?

Start this topic in reading order → · See the whole reading path

  • A tree edge is a one-vertex interfaceA tree must be colored black or white, with no edge joining two black vertices. Count all valid colorings. On a three-vertex path, coloring the middle black immediately restricts both endpoints.
  • At most one child can take a special edgeYou’re given a tree. You may mark an edge if neither of its endpoints touches any other marked edge. Find the maximum number of edges you can mark. At a branch, several children can compete for the same parent.
  • Collapse an interval of allowed labels to its endpointsEach tree vertex receives one value from its given interval. An edge earns the absolute difference between its endpoints’ values. Choose the values to maximize the sum over all edges, remembering that one vertex’s value affects every incident edge.
  • Choose tree edges with a different degree quota at each vertexEach tree edge has a profit, and each vertex has a limit on how many incident edges you can keep. Choose edges to maximize total profit within all vertex limits. At a center with profits 7, 4 and 2 and a limit of two, only two slots are available.
  • Keep a path open for the parent or close it through this vertexEach vertex of a tree has a weight, which may be negative. Choose a nonempty path that visits no vertex twice. Its score is the sum of the weights of the vertices it visits, including both ends. Find the largest possible score.
  • Merge a child’s size or budget distributionA tree is rooted at a specified vertex. Choose a set of vertices that includes that root and stays connected by edges entirely inside the set. For each possible set size, count the choices. Taking a descendant can force its connecting ancestors into the set.
  • A prerequisite tree can become a linear jump DPItems form a rooted tree of prerequisites. An item has a cost and a value, and taking it requires taking every ancestor on its path to the root. Under a fixed budget, choose a legal collection with maximum total value.
  • Send messages in both directionsYou’re given an unweighted tree. Treat each vertex in turn as a meeting point and add the distances from it to every vertex. Return one sum per possible meeting point. Start with the path 0–1–2–3, where distance is the number of edges traveled.
  • Send each child the contribution of all its siblingsYou’re given a tree and a modulus, which can be composite, such as 6. For every vertex v, count the connected vertex sets that include v, modulo that number. A singleton counts, and a set is connected only if its vertices can reach one another inside the set.
  • Reroot a sum of squared distancesSuppose you can build a station at any vertex of a tree. For a candidate location, each destination contributes the square of its distance from that location. Compute the total for every possible station. Moving the station one edge changes the distances of two groups of destinations.
  • Answer a subtree query after changing the rootEach vertex has a value. The tree is stored with root 1, but a query names a temporary root r and a vertex u. Return the sum of the values below u, including u, when parent and child relationships are interpreted from r.
  • Sparse marked vertices and virtual-tree DPYou’re given a large fixed tree with distances on its edges. Each query marks a small set of vertices. Find the total length of the smallest connected subtree containing the marked vertices, counting a shared portion of a path only once.

Test your recognition
An all-roots tree DP wants a product of child messages modulo 12. How do you exclude exactly the child you are sending to?

Use prefix and suffix products over neighbours. An individual factor may have no inverse modulo 12, even when it is nonzero.

A subtree reports a path worth 18 that already uses two child directions. May its parent extend that path?

Passing the current vertex toward its parent consumes another direction. The parent can extend only an open path with one child arm. A two-arm path is complete.
