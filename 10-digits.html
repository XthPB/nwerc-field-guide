Digit DP, binary bounds and carries

Count the integers in a range whose decimal digits satisfy a rule, such as a digit sum divisible by three. Use an upper bound of 25. After choosing a first digit of 1 or 2, which second digits are still legal?

Start this topic in reading order → · See the whole reading path

  • Translate an enormous numeric interval into a short stringYou’re given an inclusive range of nonnegative integers. Count those whose decimal representation has at most one nonzero digit. For 10 through 25 you can check by hand, but in a large range you cannot visit every integer.
  • Make leading zeros and the actual number zero behave correctlyCount the integers from 0 through 20 whose ordinary decimal writing contains a zero. The number 0 is written as one zero, while 7 is written as 7, with no leading zeros. Those conventions affect the answer.
  • Handle a bound with ten thousand decimal digitsThe upper bound K arrives as a long string of decimal digits. Count positive integers at most K whose digit sum is divisible by a given D. K can be too long to fit in an integer type, so the algorithm must work with its digits.
  • Sum digits, sum values, or compute moments without a sum axisYou’re generating decimal numbers one digit at a time. Instead of listing every valid number, you must return the sum of their numerical values. If the prefixes 1 and 3 are both allowed and each acquires the final digit 5, what should happen to the sum you store?
  • Construct the k-th number satisfying a digit ruleList the positive integers at most 30 whose decimal digits increase strictly from left to right. Order them by numerical value and return the fourth integer on the list. For a large bound and rank, listing all valid integers would take too long.
  • Attach a residue, digit mask, position, or automatonCount the positive integers in a range that are divisible by every nonzero digit appearing in their own decimal representation. For instance, a number containing both 2 and 3 must pass both divisibility tests. A digit 0 adds no divisibility requirement.
  • Digit products can return from above the limitGiven an upper bound, count positive integers whose decimal digits have product at most 5. An internal zero makes the whole product zero. When building a candidate beginning with 9, later digits can still affect whether it qualifies.
  • Count bounded numbers avoiding a digit patternCount integers between 10 and 25 inclusive whose decimal writing does not contain 12 as consecutive digits. A number can be inside the allowed range yet fail the pattern condition, so the construction must enforce both.
  • Choose and order actual digitsYou have digit tiles 1, 1 and 2. Use every tile exactly once to write a number and count distinct results. Exchanging the identical 1 tiles does not produce a different number. In variants that allow a zero tile, the first digit may need a separate rule.
  • Change direction for arithmetic carriesChoose an ordered pair (a,b) of nonnegative two-bit integers, so each lies between 0 and 3. Count pairs with ordinary sum equal to binary 10, which is decimal 2. Align their bits by position just as in written addition.
  • Count bounded pairs whose binary addition has no carryChoose an ordered pair of integers a,b between 0 and 3 inclusive. Count the pairs for which ordinary addition gives the same integer as bitwise XOR. A carry out of a bit position changes how the two operations compare.
  • Classify a large binary number by its popcountYou’re given an upper bound N in binary and a number k. A move replaces an integer by its number of set bits. Count positive integers at most N that first reach 1 after exactly k moves. Starting at 1 uses zero moves.
  • Enforce an XOR bound on every pair in a subsetYou’re given the labeled numbers 0, 1, 2 and 3. Select a nonempty subset. Every pair of selected numbers must have bitwise XOR at most 2. Count the qualifying subsets, including singletons, which have no pair that could violate the rule.

Test your recognition
Count numbers containing a real digit zero in [1,N]. Would ordinary fixed-width leading zeros work?

Keep started and seenRealZero flags. Padding before the first nonzero digit leaves both unchanged. Handle the actual integer zero separately if it enters the requested interval.

You want the sum of qualifying numbers, not a histogram of their values. What extra information does each machine state need?

A count and a sum. Appending digit d in base b sends (count,sum) to (count,b·sum+d·count).
