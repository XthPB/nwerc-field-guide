Turn past connected components into fixed subtrees

Edges disappear over time and a query extracts the largest still-available value in the current component. Reverse time fixes connectivity. How do you still process the value extractions in forward order?

Work through the example

  1. Take A–B–C with values 4,9,6. Before BC is deleted, asking at A extracts 9. After deletion, a query at C must still return 6.
  2. Read connectivity changes backward. At every successful union make a fresh parent whose two children are the old component roots. At each query remember the current root. The component containing A before deletion is now a permanent node with leaves A,B,C.
  3. Order just the original leaves by a DFS. The descendants of each saved root form one interval. Replay the queries forward. Get the maximum and its position on that interval, output it, and zero the leaf.

Why it works

The union tree preserves all earlier component memberships even after a larger component is formed. Deleting a value changes only one leaf. The same deletion is therefore visible in every later interval containing that vertex.

When the conditions change

The contest uses positive initial values and zero denotes a depleted vertex. For arbitrary signed values keep an explicit empty marker. There are at most 2V−1 union-tree nodes in total. Construction uses DSU and each extraction costs O(log V).

Try one change

Why can't you extract the values while running backward?

Show the reasoning

Which value is available depends on earlier forward queries. Only membership is independent of their answers.
