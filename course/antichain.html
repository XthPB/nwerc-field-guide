Use an ordering constraint to reduce a two-dimensional choice

Rectangles must increase strictly in both width and height. How can an algorithm for increasing subsequences avoid stacking two rectangles of equal width?

Work through the example

  1. For sizes (2,3),(2,4),(3,5), sorting both coordinates ascending gives heights 3,4,5. The apparent length three illegally reuses width 2.
  2. Sort width ascending and, within a tie, height descending. The heights become 4,3,5. Any strict increasing subsequence uses at most one width-2 rectangle.
  3. Run strict LIS on the heights and keep predecessors if a chain is required.

Why it works

Sorting enforces the first coordinate. The tie convention makes violating strictness on it incompatible with increasing in the second. CF 4D also filters out envelopes that cannot contain the starting card.

When the conditions change

O(n log n). For weighted chains, query a range maximum on prior heights and process equal first coordinates as a batch. CF 650D asks which layers remain available after a hypothetical replacement.

Try one change

Would sorting ties in descending order still be correct for a problem explicitly allowing equal widths?

Show the reasoning

The restriction has changed. Choose a tie convention and query timing that allow legal equal-width predecessors.
