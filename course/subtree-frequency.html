Trees and paths · 10 of 14

Count colors that cross a frequency threshold in a subtree

Each vertex of a fixed rooted tree has a color. A query gives a vertex v and a threshold k. Count distinct colors that occur at least k times among v and its descendants. Naming a different v selects a different subtree of the same rooted tree.

Work through the example

  1. Flatten the tree by DFS. Suppose one queried interval contains red, blue, red. Maintain freq[color] and atLeast[t], the number of colors whose current frequency is at least t. Initially both are empty.
  2. Adding the second red moves red from frequency one to two. It crosses exactly threshold two, so increment only atLeast[2]. Removing a red from frequency two reverses that same update.
  3. Process many subtree intervals in Mo order. Move each end, maintaining the two arrays, and report atLeast[k]. An alternative tree traversal keeps the heavy child's data and adds the light subtrees.

Why it works

Going from f to f+1 changes the predicate frequency≥t for exactly t=f+1. Hence each single-vertex move updates one threshold entry, even though a query may ask for any k.

exact⁡(k)=atLeast⁡(k)−atLeast⁡(k+1)\operatorname{exact}(k)=\operatorname{atLeast}(k)-\operatorname{atLeast}(k+1)exact(k)=atLeast(k)−atLeast(k+1)

When the conditions change

With a square-root block size the static Mo approach costs O((n+q)√n) typical worst-case pointer work, plus sorting queries. Compression gives O(n) frequency space. The heavy-child approach also works here because every query is a subtree.

Try one change

If the query asks for exactly k occurrences, how can the same table help?

Show the reasoning

Subtract atLeast[k+1] from atLeast[k]. For k≥1 both entries count only colors present in the interval.
