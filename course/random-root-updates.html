Turn a random-root path update into component sizes

An update specifies v and an increment d, then picks a tree vertex uniformly as a root. A vertex u receives d exactly when the path from the chosen root to u contains v. After several updates, answer queries for the expected accumulated value at a requested vertex.

Work through the example

  1. On A–B–C, update B by 6. B always gains 6. For target A only roots B and C give a path through B, so A gains 4 in expectation. The same goes for C.
  2. Remove v. For a target in a remaining component of size s, exactly n−s roots qualify. The contribution is d(n−s)/n. Root the original tree once. Every child component is an Euler subtree and the parent component is its complement. Apply constant additions over these sets, and give v the full d.
  3. A high-degree v could touch too many ranges. At low-degree vertices apply all updates immediately with a range-add/point-query Fenwick tree. At vertices of degree above B accumulate d lazily. On a query, evaluate each such heavy vertex's coefficient by identifying the branch containing the target.

Why it works

Linearity lets you add expectations from separate updates. The identity of the random root within its side of the separating edge is immaterial. There are fewer than 2n/B high-degree vertices because the sum of degrees is 2(n−1).

ΔE[Xu]=dn−sn(u≠v)\Delta \mathbb{E}[X_u]=d\frac{n-s}{n}\quad(u\ne v)ΔE[Xu​]=dnn−s​(u=v)

s counts the component of u after removing the update vertex v.

When the conditions change

With Euler times and binary lifting, low-degree updates cost O(B log n) and queries cost O((1+n/B) log n). For a heavy ancestor find the child on the path to the target. Otherwise use the parent component. Treat u=v separately and invert n for modular expectations under the source modulus.

What if the root is sampled with unequal probabilities?

Show the reasoning

Replace the component's vertex count divided by n with its total sampling probability. The same branch decomposition works.
