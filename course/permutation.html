Use cycle structure to count and realize swaps

The permutation [2,3,1,5,4] must become the identity under arbitrary pair swaps. Can the operation count be proved optimal?

Work through the example

  1. The cycles are (1 2 3) and (4 5). A cycle of length k can be split into k fixed points with k−1 swaps.
  2. The total is (3−1)+(2−1)=3. A single swap changes the number of cycles by exactly one, so fewer swaps cannot reach five cycles.
  3. If swaps are allowed only along certain edges, first find connected components. Along an undirected connected graph, swaps on edges generate every permutation within that component.

Why it works

Cycle decompositions separate independent work. The “increase number of cycles” lower bound and the splitting construction meet. If a problem asks for disjoint swaps in rounds, each position can participate only once per round, which changes the scheduling part.

When the conditions change

O(n) decomposition. CF 500B combines reachable swaps with lexicographically smallest placement. CF 1675D follows parent pointers to cover a rooted tree by vertical paths, a related decomposition with different constraints.

Try one change

If equal values are interchangeable, is the permutation mapping unique?

Show the reasoning

No. Different assignments of equal copies to target positions can have different cycle counts.
