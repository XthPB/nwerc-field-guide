Can every sum between the extremes occur?

A full rectangular grid contains only +1 and −1. Start in the upper-left cell, move right or down, and finish at the lower-right. Add the values of all visited cells, including both corners. Decide whether some route has total exactly zero.

Work through the example

  1. Take two rows [1, −1, −1] and [1, 1, −1]. The three routes RRD, RDR and DRR have totals −2, 0 and 2.
  2. Exchange one adjacent right-down pair for down-right. The two routes share the endpoints of this small square. Only its middle cell changes, so the total changes by −2, 0 or 2.
  3. Any monotone route can become any other by these exchanges. Walk from a minimum route to a maximum one. Every intermediate total of the same parity must be visited, even if the totals sometimes go backwards.

Why it works

Compute the smallest and largest sum at every cell from its top and left neighbors. Start both tables at the first cell’s value. At the destination, check that the target lies inside the interval and has the parity of the number of visited cells.

When the conditions change

One row of each table gives O(columns) memory and O(rows × columns) time. Obstacles can disconnect the route-exchange graph. Larger cell values can jump over attainable-parity targets.

Try one change

If the two middle cells on a 2 × 2 board are −3 and +3 and both endpoints are zero, is +1 attainable?

Show the reasoning

No. The only sums are −3 and +3. Bounding and checking parity would accept +1.

From idea to code

Two-state DP with rolling layers

Read the executable Python reference

These functions illustrate the core algorithm. The fourteen references have differential checks against independent small-instance solvers.

def grid_sum_possible(grid, target=0):
    """Full rectangular grid of +1 and -1, with down/right moves."""
    low, high = [float("inf")] * len(grid[0]), [-float("inf")] * len(grid[0])
    low[0] = high[0] = 0
    for row in grid:
        for j, cost in enumerate(row):
            low[j] = cost + min(low[j], low[j-1] if j else float("inf"))
            high[j] = cost + max(high[j], high[j-1] if j else -float("inf"))
    return low[-1] <= target <= high[-1] and (target - low[-1]) % 2 == 0
