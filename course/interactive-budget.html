Turn an adaptive strategy into a worst-case query bound

A hidden value lies among 16 possibilities and each answer is yes or no. How many questions must a strategy allow, and when is that enough?

Work through the example

  1. A depth-three decision tree has at most eight leaves, so three questions cannot identify 16 outcomes.
  2. Four questions can suffice if each query splits the current set into equally sized legal halves. A restricted query language may forbid those splits.
  3. Track a potential equal to the surviving candidates. Bound its worst-case shrinkage and reserve queries for final disambiguation.

Why it works

CF 679A restricts queries to divisibility, requiring prime-square checks as well as distinct prime divisors. CF 835E uses bit-partition queries to separate hidden indices. For randomized queries, separately account for success probability and worst-case query count.

When the conditions change

Flush output on real interactive judges; stop immediately on the judge’s error signal. Use a local oracle to verify every hidden choice for small sizes. Some archived tasks have a different offline format.

Try one change

Can a candidate-counting information bound alone prove a four-query strategy exists?

Show the reasoning

No. It proves only a lower bound. Show that the four questions can be expressed using the allowed operations.
