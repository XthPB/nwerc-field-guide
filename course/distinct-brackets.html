Count distinct balanced substrings by giving each a suffix owner

Count different balanced bracket strings present as substrings. Occurrences may overlap, and equal strings starting at different positions count only once.

Work through the example

  1. In “()()”, starts 0 and 2 both produce “()”. Start 0 also produces “()()”. In suffix-array order “()” precedes “()()”. Their LCP is 2, so the longer suffix contributes only its valid length 4.
  2. With prefix balances P[0..n], a substring starting at i and ending just before e is balanced when P[e]=P[i] and no intervening balance falls below P[i]. Find the first later smaller balance with a monotone stack. Index the sorted positions of each balance value.
  3. For suffix i let h be its LCP with its previous suffix in lexicographic order (zero if first). Count positions e with e>i+h, the same balance, and e before the first lower balance. Use two binary searches in the bucket for P[i].

Why it works

All strings sharing a given prefix form one consecutive suffix-array interval. Of the prefixes of this suffix, exactly lengths 1 through h have appeared before. The balance conditions characterize the surviving lengths that form complete bracket strings.

e>i+LCPprev,P(e)=P(i),e<firstLower(i)e>i+\mathrm{LCP}_{\rm prev},\quad P(e)=P(i),\quad e<\mathrm{firstLower}(i)e>i+LCPprev​,P(e)=P(i),e<firstLower(i)

The candidate substring is half-open [i,e). The first condition assigns it a unique suffix owner.

When the conditions change

O(n log n) time with a standard doubling suffix array and linear-time LCP construction, plus O(n log n) for endpoint searches. Include position n in the balance buckets and use n+1 when no lower balance exists.

Try one change

Why is comparing with only the preceding suffix sufficient?

Show the reasoning

If any earlier suffix shares a prefix, every suffix in between shares it as well. The immediate predecessor reaches the greatest previously seen prefix length.

From idea to code

The suffix array and LCP settle ownership. The remaining lookup is a binary search for matching prefix-balance endpoints within an open upper boundary.
