Range queries and sweeps · 4 of 12

Maintain a count of subarrays when a query endpoint moves

Many static interval queries ask how many subarrays XOR to a fixed k. How can adding just one array position change the answer in constant time?

Work through the example

  1. Build prefix XOR with P[0]=0. For [1,2,1], the prefix values are 0,1,3,2. With k=2 the pairs (0,2) and (1,3) of prefix values contribute two subarrays.
  2. The array interval [l,r] in one-based indices corresponds to prefix indices [l−1,r]. Count unordered pairs of distinct positions whose values differ by XOR k. Inserting x adds freq[x XOR k] pairs, then increments freq[x].
  3. Sort queries with Mo's algorithm and add or remove prefix positions at either endpoint. To remove x, first decrement its frequency and then subtract freq[x XOR k].

Why it works

Every subarray has a unique earlier and later prefix index. Its XOR is the XOR of exactly those two prefix values. A pair is created when the second member enters and destroyed when the first member leaves.

xor⁡(l,r)=Pl−1⊕Pr\operatorname{xor}(l,r)=P_{l-1}\mathbin{\oplus}P_rxor(l,r)=Pl−1​⊕Pr​

When the conditions change

The subtraction order matters when k=0, because the partner lookup uses the same bucket. Static queries with one fixed k allow one shared state, O((n+q)√n) pointer moves with square-root blocks, plus sorting.

Try one change

Why does [l,r] need P[l−1] as well as the prefixes through r?

Show the reasoning

P[l−1] pairs with an end prefix to represent every valid subarray that starts exactly at l.
