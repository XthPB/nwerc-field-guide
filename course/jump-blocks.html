Range queries and sweeps · 17 of 19

Jump to the next block and remember the last visited cell

An array specifies a positive jump length at every position. Starting at i, keep jumping forward until you leave the array. Report the last position inside and the total number of jumps, counting the exit jump. Point updates change how far one position sends you.

Work through the example

  1. Split six positions into [1,2,3] and [4,5,6]. With jumps [1,2,1,2,1,2], starting at 1 follows 1→2→4, then 4→6→outside. The summaries for 1 and 4 give four jumps and last cell 6.
  2. For each i store its first destination outside its own block, its number of jumps to that exit and the last cell before exit. If the first jump stays in the block, inherit these fields from its successor and add one jump. Otherwise store that one jump directly.
  3. Fill each block from right to left. Changing a value can alter cached summaries only in its own block. Recompute that block. For a query repeatedly take one block exit and add its jump count.

Why it works

Each summary ends before consulting the jump rule of any later block. Changes elsewhere leave it valid. Positivity forces block exits to advance, giving at most one summary lookup per visited block.

When the conditions change

With blocks of size B, update O(B), query O(n/B+1), memory O(n). Balance related workloads with B near √n. A jump can skip whole blocks.
