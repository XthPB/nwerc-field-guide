Graphs, connectivity and flow · 26 of 27

Undo both connectivity and XOR-cycle information

Weighted undirected edges appear and disappear. At a query time, find the smallest XOR along a walk between two vertices. How can information about a deleted cycle be removed again?

Work through the example

  1. A path A–B–C with weights 3 and 5 has XOR 6. Adding an A–C edge of weight 2 introduces cycle XOR 4. Toggling it changes 6 to 2. Removing that edge must remove this option.
  2. Put each edge's lifetime into the segment tree over query time. During DFS keep a rollback union-find with XOR-to-parent. If endpoints are in different components, join their roots with the XOR required by the edge. Otherwise insert its cycle XOR into a binary linear basis.
  3. At a query compute the forest path XOR from the two root potentials. Try pivots from highest bit to lowest, accepting a toggle if it reduces the answer. When leaving a time-tree node undo its new pivots and unions back to the saved checkpoints.

Why it works

Any walk differs from a fixed forest path by cycles. The fundamental cycles generate all those XORs. In a connected undirected graph you can visit a selected cycle and return to your route along a detour whose edges cancel in pairs.

When the conditions change

The contest guarantees connectivity at query times, so a global basis works at a leaf. For disconnected queries keep bases by component. Use a pivot insertion that only fills one empty slot and rollback DSU without path compression. For M edge lifetimes over Q times and B weight bits, O(M log Q (log n+B)+Q(log n+B)) time.

Why does a minimum spanning tree not solve this?

Show the reasoning

XOR lacks the edgewise ordering used by the spanning-tree cut argument. A cycle can improve a route even when it adds more edges.

From idea to code

Use the rollback XOR forest for edge insertion. Send each returned cycle XOR to a high-bit-first basis and log its newly filled pivot, if any.
