Compress all subarrays ending here into a short gcd list

For many targets g, count all subarrays with gcd exactly g. There are quadratically many subarrays. How much distinct information survives at one right endpoint?

Work through the example

  1. For [6,10], the subarrays ending at 10 have gcd 10 and 2. Store each gcd with the number of starts attaining it.
  2. Append 15. Start a singleton (15,1), extend (10,1) to (5,1), and (2,1) to (1,1). If adjacent groups acquire the same gcd, sum their counts.
  3. Add those group counts to a global table. Move to the next endpoint retaining only the new groups. At the end each query is one lookup.

Why it works

As the left boundary moves left, each new gcd divides its predecessor. For positive integers a strict proper divisor is at most half as large, so the list contains only O(log A) distinct values, where A is the largest input value.

When the conditions change

There are O(n log A) gcd calls. Charge their arithmetic cost separately if required. Multiplicities preserve different starts that collapse to one gcd. The positive-input bound needs an extra zero case when generalizing.

Try one change

Can you keep just a set of gcds instead of multiplicities?

Show the reasoning

A set answers which gcds exist. With [4,4], two different subarrays ending at the second position have gcd four.
