Count valid decimal cuts with two boundary comparisons

Split a long digit string into integers between two large bounds. The chunks must use canonical decimal notation. How do you compare all candidate chunks without parsing enormous integers?

Work through the example

  1. Take 123 with allowed numbers 2 through 23. Starting at the first digit, length one fails because 1<2. Length two gives 12; the remaining 3 succeeds, so 12|3 works. No longer first chunk can fit.
  2. At each starting index, all lengths strictly between the bounds' digit lengths are automatically in range when the first digit is nonzero. Only the two boundary lengths need lexicographic comparisons. Precompute longest common prefixes with each bound using a Z array on bound, separator, and text.
  3. For a nonzero start the valid cut endpoints form one interval after the two boundary checks. Send its number of ways to that interval using difference-array additions, then read the running sum at the next position. At a zero start allow only the single digit 0, and only when 0 lies in the bounds.

Why it works

Canonical positive decimal representations are ordered first by length and then lexicographically among equal lengths. Each range addition distributes exactly the previous prefix count to every legal next cut. Taking a prefix sum recovers all incoming contributions.

When the conditions change

O(n+|L|+|R|) time and space with precomputed Z values. If the bounds have equal digit length, the one candidate must pass both tests. Handle a chunk ending at the final index and reduce differences modulo the requested modulus.

Try one change

For 101 and bounds [0,10], is 1|01 allowed?

Show the reasoning

No. The internal chunk has a leading zero. Both 10|1 and 1|0|1 are allowed.
