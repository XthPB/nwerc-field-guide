Spend component resources in a legal spanning-tree order

An undirected graph connects towns with initial resources. Merge two groups only along an existing edge between them, and pay x from their pooled resources on each merge. Return an order of n−1 edges that joins all towns without ever spending more than the two groups have.

Work through the example

  1. Take a chain A–B–C with resources 1,1,8 and cost 4. Joining A and B first fails. Joining C to B leaves 5 in their component, enough to join A.
  2. Choose a spanning tree and process its vertices in postorder. When a child's accumulated resource is at least x, schedule its parent edge now and credit the parent with the surplus. Otherwise put that edge on a deferred list and leave the child's resource in place.
  3. Output the immediately scheduled edges in discovery-of-completion order, then the deferred edges in reverse. In the example root at A. C pays to join B, then B's component pays to join A.

Why it works

After the first phase each deferred child component has resource c<x and costs a net x−c to absorb. The component containing the root has at least the sum of all these deficits whenever the original total is at least (n−1)x. Reverse postorder attaches each deferred component after its parent has joined the root, so funds are available at every step.

When the conditions change

Check connectivity and the total first. Any spanning tree suffices. O(n+m) time and O(n+m) space. An iterative postorder avoids exhausting the call stack on a long chain.

Try one change

What if every vertex starts below x?

Show the reasoning

Joining remains possible if pooled resources cover each deficit. The total-resource proof still applies.

From idea to code

The tree traversal supplies the postorder. Store original edge IDs in the immediate and deferred lists, then reverse only the deferred list.
