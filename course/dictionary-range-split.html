Strings and pattern matching · 17 of 17

Choose which side of a dictionary query to precompute

Each query specifies a range of dictionary entries and one dictionary string to use as text. Count all occurrences of entries in that range inside the text, including overlaps. A popular long text can be queried many times.

Work through the example

  1. For entries [“a”,“aa”,“aba”], querying entries 1..2 inside “aa” gives 3. The same occurrence engine should also answer which entries matched a long text across many different index ranges.
  2. For short texts (length ≤B), express [L,R] as two prefix queries. Sweep dictionary index j, activating pattern j by adding one to its terminal's failure-tree subtree in Euler order. Each scanned text prefix contributes the current point value at its automaton state.
  3. For each distinct queried long text, scan it once and count visits to states. Propagate these counts from deeper states to their failure parents. The visit total at each dictionary terminal is now that pattern's occurrence count. Prefix-sum in dictionary index order and answer all queries for this text by subtraction.

Why it works

One occurrence can be counted from either side. A pattern terminal is an ancestor of the text prefix state exactly when the pattern ends there. Short texts make repeated scans cheap. Long texts make whole-dictionary preprocessing worthwhile, and there are at most S/B such dictionary indices when total text length is S.

When the conditions change

Using a subtree-add/point-query Fenwick tree, time is O((S+qB)log S + S²/B + q). Reuse count arrays for each long text to keep memory O(S+q) for a fixed alphabet. Duplicated dictionary entries count separately.

Try one change

Why can activating a pattern on just its terminal lose occurrences?

Show the reasoning

At the end of “she”, “he” lives at a failure ancestor. A subtree add makes that terminal active at all its matching descendant states.

From idea to code

The same Aho automaton supports both directions of counting. Euler-index the failure tree for short queries and save reverse BFS order for long-text propagation.
