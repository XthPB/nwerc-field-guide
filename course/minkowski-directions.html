Count polygon-sum sides as distinct directed edge directions

You’re given a list of convex polygons. A query selects consecutive polygons and asks for the number of sides in their Minkowski sum, the shape formed by adding one point from each polygon. Count the straight boundary sides after merging adjacent edges in the same direction.

Work through the example

  1. A square and an axis-aligned rectangle both have four directed edge directions. Their Minkowski sum also has four sides. Add a triangle with edges pointing east, northwest and south. Only northwest is new, so the union contains five directions.
  2. Normalize every convex polygon to a consistent boundary orientation. Replace each edge vector by (dx/g,dy/g), where g is the gcd of the absolute coordinates. In a Minkowski boundary merge, parallel edges going the same way produce one side.
  3. Sweep polygons by right endpoint. For each direction store a 1 at its most recent polygon in a Fenwick tree, clearing its old mark. One polygon index may carry many marks. Queries ending here count marks in [L,R].

Why it works

For a direction of support, the exposed face of the sum is the sum of the exposed faces. As the normal rotates, an edge appears exactly when at least one summand has an edge with that outward normal. Last occurrences count each such oriented direction once per queried range.

When the conditions change

For E edges, n polygons and q queries, O((E+q) log n) tree time plus normalization and dictionary costs. Remove zero-length edges and merge collinear boundary runs as needed. Opposite vectors define distinct sides.

From idea to code

Normalize a signed edge vector by its positive gcd. Update one old and one new polygon index in the Fenwick tree whenever a direction appears again.
