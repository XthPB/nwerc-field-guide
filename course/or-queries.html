Ask overlapping questions that omit each target in turn

There is a hidden integer at each of n positions. You may name a subset and receive the bitwise OR of its values. With a small fixed query budget, produce for every i the OR of all positions other than i. One query answer may contribute to several outputs.

Work through the example

  1. Give three indices the labels 001,010,100. For each bit query all indices whose label has zero at that bit. To answer for 001 take the query at its one bit. It omits that index and includes both others.
  2. For more indices use distinct B-bit labels all of the same Hamming weight. For a target i, combine all queries corresponding to its one bits. Every such query excludes i. For a different label j there is some bit where i has one and j has zero, so j is included.
  3. OR the selected query responses. Overlap is harmless because OR is idempotent. With B=13 there are 1,716 weight-six labels, enough for the contest's bound of 1,000 positions. An empty query can be skipped and treated locally as zero.

Why it works

Equal-size distinct subsets cannot contain one another, giving the required distinguishing bit for every ordered pair of indices. The argument constructs a nonadaptive query family before any hidden values are known.

When the conditions change

The construction also works for idempotent associative, commutative operations with a known identity for an empty set. Summation would count overlaps several times. Building and combining these queries uses O(nB) work.

Try one change

Why can using arbitrary binary encodings of the positions fail?

Show the reasoning

If the one bits of i form a subset of those of j, no query selected for i is guaranteed to contain j. An equal-weight family rules out this containment.
