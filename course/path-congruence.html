Trees and paths · 14 of 14

Combine centroid decomposition with path direction and modular inverses

Each edge of a tree carries a decimal digit. An ordered pair of different vertices defines a number by reading the edge digits along the path from the first to the second. Count the pairs giving a multiple of m, where m is coprime with 10. Reversing a path can change its number.

Work through the example

  1. At a centroid C, store U(u), the number read from u up to C, and D(v), the number read from C down to v. For a path crossing C the number is U(u)·10ᵈᵉᵖᵗʰ⁽ᵛ⁾+D(v).
  2. If m=7, the concatenated digits 2 then 1 form 21, divisible by 7. Reading 12 in the other direction fails.
  3. For a given endpoint v the needed starting residue is −D(v)·10⁻ᵈᵉᵖᵗʰ⁽ᵛ⁾ mod m. Count complementary residues from different branches, treating C as an empty digit string.

Why it works

Count ordered pairs through the centroid by a global histogram minus within-branch histograms, or by sweeping branches with both directions accounted for. Paths entirely inside one branch are handled recursively.

When the conditions change

Typical O(n log n) expected time with hash counters, or O(n log² n) with ordered maps. Exclude the zero-length path when endpoints must differ. Leading zero digits still consume depth. Multiplicative inverses of 10 exist only under the coprimality promise.

Why does counting unordered compatible pairs and doubling fail?
