Range queries and sweeps · 4 of 19

Find the first eligible x, then the least eligible y

You maintain points (x,y) under insertions and deletions. A query gives (x₀,y₀). Among points strictly to its right and strictly above it, return the leftmost one. If several have that same x, return the lowest of them. Report when no point qualifies.

Work through the example

  1. With (2,9),(5,2),(5,8),(7,6), query (2,5). Begin after x=2. Column 5 contains a value above 5, so it wins even though column 7 has a smaller eligible y. The answer is (5,8).
  2. Compress the x coordinates. At each column keep its live y values in an ordered set. Store the column maximum in a segment tree. Search left child first after the starting index and skip whole nodes whose maximum is at most y₀.
  3. In the first surviving column use upper_bound(y₀). On an edit change that column's set and refresh its maximum. An empty column has a value below all queries.

Why it works

The maximum certifies whether a column interval contains any eligible y. Left-first descent returns the smallest feasible x. The final ordered lookup enforces the secondary y criterion, even when the maximum itself is larger than needed.

When the conditions change

O(log n) per operation after compression. Compress inserted coordinates even if the structure starts empty. Both inequalities in this variant are strict. For duplicates use counts if deletion removes only one copy.

Try one change

How would you return the largest b anywhere in a fixed a-range instead?

Show the reasoning

Store (b, original index) as the node aggregate and query the compressed interval directly. Pick a deterministic tie-break for equal b.

From idea to code

Use one FirstAbove leaf per compressed x. Start from upper_bound of the query x. The final lookup is another upper_bound in that column’s ordered y values.
