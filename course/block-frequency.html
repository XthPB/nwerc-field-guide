Range queries and sweeps · 16 of 19

Use two scales when an update shifts many query candidates

For each index i, you have an integer score sᵢ and weight wᵢ. Update many scores by the same offset in an interval and sum weights of all scores ≤k. A segment sum alone lacks the distribution.

Work through the example

  1. Split the indices into blocks of B. In each store a lazy offset and a sorted list of raw scores with cumulative weights.
  2. A fully covered block shifts only its offset. A threshold query binary searches k−offset and reads the corresponding cumulative weight.
  3. At either partially covered boundary materialize the old offset, edit the affected scores and rebuild the block. For raw scores [0,2,2] with weights [4,1,3] and offset 1, threshold 3 admits all 8 units.

Why it works

The offset preserves score order within a block. Size B balances work rebuilding boundary blocks against scanning n/B summaries. CF 1129D has a sharper histogram version using local ±1 differences. In CF 103D the small/large split is by step length rather than index.

When the conditions change

With comparison sorting, two partial rebuilds cost O(B log B) and a full threshold query O((n/B) log B). Restricting scores to a small integer range can remove log factors. Point weight insertions also require updating or rebuilding that block’s cumulative weights.
