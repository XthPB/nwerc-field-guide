Double the ranked prefix when indices are permuted by XOR

You’re given a string of length 2ⁿ and may choose a single n-bit mask m. At output position i, write the original character at position i XOR m, using zero-based indices. Among all masks, return the lexicographically smallest complete output string.

Work through the example

  1. For “caba”, the four candidates start at the characters c,a,b,a. Masks 1 and 3 tie on the first letter. At length two their prefixes are “ac” and “ab”, so mask 3 wins that tie. Its finished word is “abac”.
  2. Initially rank every mask by its first character s[m]. If rank[m] describes its first 2ʰ characters, the next equally long block has rank rank[m XOR 2ʰ]. Sort all masks by the ordered pair of ranks and assign the same fresh rank to equal pairs.
  3. Repeat until the prefix is the full string. Choose any mask with the smallest final rank and output the actual characters in XOR order.

Why it works

For 0≤j<2ʰ, (2ʰ+j) XOR m equals j XOR (m XOR 2ʰ). Thus the second block is literally another candidate's already ranked first block. Pair ordering respects the first differing character.

Rₕ ranks a prefix of length 2ʰ among all XOR masks.

When the conditions change

N must be a power of two. Comparison sorting gives O(N log² N) time and O(N) space. Stable counting sorts on the integer ranks reduce this to O(N log N). Use zero-based indices.

Try one change

Why can't we rank a candidate by the multiset of its two half ranks?

Show the reasoning

Reversing the order of distinct halves changes the first differing character. The pair must be ordered.

From idea to code

Reuse the ordered pair compression from suffix-array doubling. The second rank is indexed by XOR with the current block length.
