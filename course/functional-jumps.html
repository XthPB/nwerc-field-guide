Trees and paths · 4 of 14

Separate the tail of a walk from its cycle

Every vertex has exactly one outgoing arrow, so a start vertex determines the entire walk. Answer where it ends after a huge number of steps, or whether it can reach another vertex. In 1→2→3→4→3, the walk eventually circles between 3 and 4.

Work through the example

  1. Peel vertices of indegree zero. The survivors are directed cycles. Label each cycle’s length, order and component ID.
  2. From 1 it takes two steps to reach 3. The remaining 10¹⁸−2 is even, so the answer is 3. Vertex 2 is on the tail and unreachable from 4.
  3. Build a jump table next[v][k] for 2ᵏ moves. For reachability, align depths on the same incoming branch or, for a cycle destination, jump to the entry and add a directed cyclic offset.

Why it works

The first repeated vertex starts the cycle. Each tail vertex has one unique forward route to a cycle, but branches can merge, so equal depths alone do not prove reachability.

When the conditions change

O(n log K) preprocessing and O(log K) per bounded jump, or use depth plus cycle reduction. CF 711D is a counting adaptation: each underlying cycle forbids its two fully directed orientations.

Try one change

Can two vertices that enter the same cycle be mutually reachable even if one is on a tail?

Show the reasoning

No. Once a walk reaches the cycle it never returns to the tail.
