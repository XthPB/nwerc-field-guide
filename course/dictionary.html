Strings and pattern matching · 6 of 17

Make failure links count every pattern ending here

Scan “ushers” for “he”, “she” and “hers”. After reading the e, two dictionary words end at the same position. How can one machine recognize both?

Work through the example

  1. Build a trie and add failure links to the longest represented proper suffix.
  2. At the state for “she”, its failure chain reaches “he”. The state therefore emits both words. The ending s later completes “hers”.
  3. Count visits to states while scanning. Propagating visits backwards along failure links gives each terminal its total number of occurrences, including overlaps.

Why it works

The current state represents the longest dictionary prefix ending at the current text position. All shorter matching prefixes lie on its failure chain. This turns queries about a pattern into subtree sums in the failure tree, as used in CF 547E.

When the conditions change

Dense transitions O(alphabet × trie size) to build and O(text length) to scan plus output costs if listing matches. CF 963D uses occurrence positions to answer repeated-pattern window questions. Patterns repeated in the dictionary may need separate output IDs.
