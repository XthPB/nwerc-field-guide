Sum many pairwise LCPs by counting shared ancestors

You’re given one text and two lists of starting positions. Each position represents the suffix beginning there. For every pair containing one suffix from each list, measure their longest common prefix and add those lengths. Return the total without listing every pair.

Work through the example

  1. For strings “ab”, “ac”, “ab”, a pair gains one unit for every shared prefix edge. For the first two strings their common contribution comes only from the “a” edge.
  2. In a trie, count how many selected A and B strings descend below each edge. That edge contributes its length times countA·countB. Compressed edges may represent several characters.
  3. A suffix tree or a Cartesian/LCP tree formed from suffix-array order supplies the same shared-prefix structure without materializing all suffix strings.

Why it works

Swap summations: charge each common prefix to the edge where both members still lie below it. For sparse queries a virtual tree of selected suffixes and their LCAs skips irrelevant branches. Count repeated list entries with multiplicity when the statement allows them.

When the conditions change

Precompute suffix ordering and LCA. Per query the compressed selected structure can be built in roughly O(k log k + k·LCA-cost), for total list size k. CF 1073G also admits a rank-order monotone-stack solution.

Try one change

Can you discard the lengths of compressed edges?

Show the reasoning

No. Each character along that edge contributes one unit to every cross-list pair below it.
