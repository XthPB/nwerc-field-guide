Advanced range queries inside DP

Move from two disjoint allowed ranges to richer node values, separate versions and entire transition operators. Keep the order of composition visible.

  • A forbidden gap can turn one predecessor query into twoChoose a long subsequence of heights where consecutive values must differ by at least 4. Which old heights can lead into h?
  • Store a witness or the number of optimizers inside each range nodeA range contains multiple equally good predecessors. Return their best score, their total number of ways and one actual route.
  • Independent rectangle bounds require a second range dimensionFind the best predecessor inside a rectangle bounded on both x and y. Can four prefix maxima answer the query?
  • Find the k-th value between two array positionsFind the second-smallest value in positions 2 through 4 of 5,1,5,2.
  • Represent a substring by its whole DP transitionLetters of a string change online. How can you recompute the cheapest edits satisfying a small automaton after each change?
  • A range update can act linearly on each stored DP valueEach array entry stores a Fibonacci index. A query adds two to every index in a range. Can you update their Fibonacci sum at once?
  • Replace a fan of interval transitions with segment-tree nodesOne offer lets you pay 4 to travel to any vertex in an entire interval. How do you build a shortest-path graph with many such offers?

Test your recognition
A range-query structure returns (best score, count). Why can two overlapping sparse-table blocks give the wrong count?

A shared maximizing predecessor contributes twice. Query disjoint blocks or use an idempotent operation when overlap is unavoidable.

Why keep separate upward and downward segment trees for an interval-to-vertex graph?

A bidirectional zero-cost tree connects unrelated leaves for free. Separate directed trees make every permitted move pass through the intended weighted offer.
